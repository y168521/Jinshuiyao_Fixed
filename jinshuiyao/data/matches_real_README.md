# matches_real.csv 真实比赛结果数据集 · 说明

> 生成：诺亚团队(WorkBuddy)｜采集日：2026-07-28｜行数：143｜列数：9
> 数据性质：**真实赛果**（非演示、非推算）。来源均为公开可核实的 2025-26 赛季已完赛场次。

## 一、为什么单独建一份，而不填进演示 CSV

`matches_supplemented.csv` 的 400 行是赛奇用 seed=42 生成的**演示数据**——球队组合、比赛时间都是编的，
不存在对应的真实比赛，因此**无法把"真实赛果"对到这些假比赛上**（那是造假，违反项目诚实铁律）。
所以真实赛果单独成文件，与演示数据**物理隔离、切勿按行号/主键直接合并**。

## 二、字段（9 列）

| 字段 | 类型 | 含义 | 示例 |
|------|------|------|------|
| match_id | string | 真实数据集编号 REAL_0001~REAL_0143 | REAL_0001 |

| 联赛 | 轮次 | 场数 | 来源 |

> 说明：来源中的"纳米数据"为 WebSearch 聚合的赛事赛果表，其比分与官方站点(英超/西甲官网、AS.com 等)
> 交叉一致；日期取自官方赛程/赛果页。少数场次仅取到轮次主日期，精确到日级足够回测使用。

## 四、⚠️ 重要缺口：本文件**不含赔率(odds)**

本数据集只有"真实赛果(result/score)"，**没有赛前赔率**。金水谣预测引擎的训练/回测逻辑是
"用赔率(odds)预测赛果(result)"，因此：

- 当前可用本文件做**真实历史赛果的统计校验**（如主胜率、各大联赛平局率等基线）。
- 要完整回测"赔率→赛果"预测准确率，**必须再接入一份真实的赛前赔率源**（如足球数据 API /
  OddsPortal 历史赔率归档），按 match_id 或 球队+日期 对齐后合并。这一步尚未做。

## 五、与演示数据的关系

- `matches_supplemented.csv`（演示，400 行，含 odds/handicap/rank/form）：用于验证**分析与管线流程**，
  结论不可当作真实赛果。其 `result/score` 列已预留为空，待真实数据回填（但演示行无真实赛果可对，留空即正确）。
- `matches_real.csv`（真实，143 行，仅 result/score）：用于**真实赛果校验/回测基线**。
- 两者用途不同，请按需在对应流程中引用，勿混用。

## 六、复现

运行 `generate_real_dataset.py` 可重建本文件（数据为硬编码的真实赛果，确定性输出，非随机）。
