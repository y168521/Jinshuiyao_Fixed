一、为什么"流程都能漏"？——根因三连

漏的不是某一步，是机制层出了问题。逐层拆：

根因① 清单本身不完整
旧"收工三步"= 总索引 + memory + commit，压根没有 §7 知识库决策卡、§8 三层闭环两项。 照着不完整的清单走，走得再认真也漏。
根因② 靠记忆纪律执行
流程写在 MEMORY / 提示词里，靠 AI"记得"去做。长会话、多轮接力、上下文压缩后， 纪律必然衰减——这不是态度问题，是人/LLM 的结构性弱点。
根因③ 无交叉核对（单点串行）
总索引登记了 JS 编号，没有任何机制去问一句"它进知识库了吗？"。 各环节各写各的、互不校验，断点无人报警。
活证据（本周亲历）：JS-20260727-01~04 全部登记进了总索引，却零张进 ai_decisions.md 知识库——直到用户追问才发现。三个根因同时命中：清单没这项 + 没人记得 + 没有交叉核对。

解法：机器强制的"完成定义(DoD)"——已落地

把完成定义写成可执行脚本，收工时机器逐条核对，缺哪项点名哪项。已新增 scripts/closeout_gate.py，四项合一：

DoD 项机器核对什么治的根因状态
[A] git 状态待提交源码/文档清单 + gitignore 隐患（内部调 git_commit_gate.py）③已接
[B] 索引↔知识库覆盖今日总索引登记的每个 JS 编号是否都进了 ai_decisions.md（历史漏网点）①③已接
[C] 今日决策卡完整今日卡是否存在、8 必填字段是否齐全①已接
[D] 三层闭环旁证启动提示词.txt 今日是否同步（弱提醒）②已接
已把每日 23:30「金水谣·收工自检」自动化的执行体从"两步人工核对"换成 closeout_gate.py 单脚本。从此不靠任何人记得——机器每天替你查，缺口自动点名。 实跑验证：今日 5 个 JS 编号 [B] 全绿、[C] 8 字段齐全、[A] 正确抓到未提交项。

二、知识如何"连锁反应"？——单一真源 + 自动传播

你要的"连锁反应、利益最大化、效率最大化"，本质是两条工程原则： ① 一件事只在一个地方写(单一真源)， ② 写一次就自动流到所有下游(自动传播)。杜绝"同一结论手抄五遍还抄漏"。

知识流转闭环（七层，环环相扣）

① 干活
写代码/回测/分析，产出事实
→
② memory 日志
当日 YYYY-MM-DD.md 追加，细节留痕
→
③ 总索引
JS 编号登记：文件/验证/遗留
→
④ 决策卡
ai_decisions.md 8 字段，沉淀"为什么"
⑤ 知识卡片+三元组
extractor 自动转，GraphRAG 可离线检索
→
⑥ Skill / 自动化
可复用工作流固化为技能+定时门禁
→
⑦ 启动提示词
铁律进唯一入口，下个 AI 启动必读
↺
回到 ①
下一轮站在全部沉淀之上开工
↑ 闭环：每一轮的产出都变成下一轮的起点，知识只增不丢 = 复利
连锁点在哪？（效率最大化）
· ④→⑤ 自动：决策卡一写，server mtime 监听线程 15 秒内自动抽成知识卡片+三元组，无需手动。
· ③↔④ 门禁：closeout_gate 强制"登记必入库"，断点自动报警。
· ⑥→⑦ 校验：启动提示词同步校验(周一)防三层漂移。
→ 一份结论写一次，检索/接力/门禁/新 AI 启动全都自动吃到。
断链会怎样？（反面教训）
· ④ 断（本周）：登记了没入库 → 知识库空转，检索搜不到。
· ⑤ 断：extractor import 漂移曾使离线检索失效(本周已修)。
· ⑦ 断：铁律没进启动提示词 → 下个 AI 重蹈覆辙。
→ 任何一环断，"复利"变"漏斗"。故每个箭头都要有门禁或自动化兜底。

三、Skill 治理：为什么"多 ≠ 有用"，怎么升级合成

核心判断：Skill 是负债还是资产，取决于"是否被唯一、清晰地触发并维护"。 数量多反而制造触发歧义（两个技能都像该用哪个？）、维护税（改一处漏改另一处）、 重叠冲突（结论打架）。所以默认优先升级/合并现有，而非新建。

决策树：遇到一个"可复用工作流"，先问四问

1
已有技能能覆盖吗？ 能 → 升级它（充实步骤/修 bug），不新建。
2
与某技能职责高度重叠吗？ 是 → 合并为一个，旧的降级为子组件或删除（需授权）。
3
是独立、边界清晰、会反复用的新能力吗？ 是 → 才新建，且 description 触发词必须与现有技能无歧义。
4
一次性 / 含敏感信息 / 已被覆盖？ 是 → 不做技能，写 memory 即可。

四、获取信息：合法合规 + 打通闭塞（一体两面）

合法合规采集红线
· 只取公开可访问的权威源（学术库/官方公告/主流媒体/官方文档）。
· 尊重 robots.txt 与站点 ToS，不绕验证码、不抓登录后私域数据。
· 不采集个人隐私、不做人肉、不碰版权受限的批量内容。
· 结论必注出处，可回溯；商用数据看授权。
· 本机执行类接口守 _is_local() + _is_safe_http_url 防 SSRF。
破信息闭塞·常设规则
· 任何"有效/无效"结论 = 内部实测 + 外部权威双证据链，缺一不立。
· 只靠内部数据自证 = 过拟合温床（本周教训：全靠回测自证，闭塞）。
· 关键结论定期联网再校准，防知识过期。
· 外部证据也要过同一把尺（三数检验/随机基准），不因"是论文"就免检。
已固化为铁律：彩票领域内外双证已互证——内部 avg_gain=+0.89%≈随机， 外部 ICCSA 论文(6/49 30年2510期≈随机)+福彩官方辟谣+曼德尔"买全组合(+EV)非预测"。 这条"双证据链"规则已写进启动提示词与提示词库，成为常设动作。
