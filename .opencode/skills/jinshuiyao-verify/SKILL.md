# 金水谣 · 动手前强制核实铁律（verify-before-claim）

> 来源：2026-08-03 实战翻车。AI（WorkBuddy）在"模型怎么优化"任务中，**凭内置记忆/印象**下了两个错误结论，被用户当场用"你实际看过没有？"反问抓出。教训：AI 内置记忆会过时，外部事实（模型名/API/版本）更是天天变。**任何结论必须先核实，否则标【待核验】并回退，不得直接写进代码或文档。**
> 本 Skill 是给"下个接手的 AI"的硬约束——无论它有没有上下文，开工前必先过这一关。

## 三条铁律（无例外）

### 铁律 V1：外部事实/模型有效性断言 → 必须联网核验
- **范围**：任何关于"某 API/模型是否存在、叫什么名、是否停用、参数怎么填"的断言。
- **做法**：用 WebSearch / WebFetch 查官方文档（DeepSeek / 硅基流动 / akshare 等），拿到**当前有效**证据再下结论。
- **禁止**：用"我记得 DeepSeek 只有 chat/reasoner"这类内置记忆直接断言。**内置记忆不是事实源。**
- **失败样例（2026-08-03 真实翻车）**：AI 断言 `deepseek-v4-pro` 是"无效模型名"、应改回 `deepseek-chat`。实际官方文档显示：v4-flash/v4-pro 是当前有效名，旧 chat/reasoner 已于 2026-07-24 停用。**结论完全反了**。根因=没联网核验就凭印象下结论。

### 铁律 V2：代码行为/是否有 bug 断言 → 必须读真实代码（grep/Read），不得凭印象
- **范围**：任何"某函数/文件干了什么""这里是不是 bug""该不该改"的判断。
- **做法**：
  1. 用 Grep 在仓库内**真实检索**关键字符串/函数名，确认它确实存在、出现在哪些文件哪些行。
  2. 用 Read 打开相关文件看上下文，确认逻辑（不要只看一行就下结论）。
  3. 必要时跑脚本/单测验证（如 `--self-test` / `check_consistency.py`）。
- **禁止**：把"我印象里这段代码是这样"当结论；**尤其禁止"听说/以为旧版是这样"就判断当前代码有 bug**。
- **失败样例**：AI 凭印象断言"蒙特卡洛用了固定种子=回测没测波动=该改"，但没先读 `montecarlo.py`。实际读后发现 `backtest_strategy(seed=None)` **默认不固定种子**，固定种子仅在 `__init__.py` 一处且不影响 `gain≈0` 结论 → 误判为"必改 bug"。

### 铁律 V3：动手改之前 → 先确认改动落点 + 验证手段
- **范围**：任何 Edit/Write 之前。
- **做法**：
  1. 改核心文件（如 `core/free_model_pool.py`、钩子、启动器）前，先确认它的**真实调用链/是否活路径**（Grep 谁 import 它、谁启动它）。
  2. 改完必须跑对应验证（自测/一致性/单测），**不靠"应该没问题"**。
  3. 工具自身故障（如钩子报错）要先区分"我的代码问题"还是"工具 bug"，**手动用正确路径跑等价检查**确认，再决定 `--no-verify` 等例外。
- **失败样例（顺带发现）**：修模型名时直接改 `.git/hooks/pre-commit`，没先查 `install_hooks.py` 发现钩子真源是 `tools/pre-commit-hook-wrapper.sh` → 改动会被重装覆盖。后查源修正。

## 核实清单（动手前逐条过）

- [ ] 我这条结论涉及外部事实吗？是 → 联网核验官方文档，附来源。
- [ ] 我这条结论说"某代码有 bug/该改"吗？是 → Grep+Read 真实代码，不凭印象。
- [ ] 我准备改的文件是活路径吗？谁 import/启动它？（核心文件尤其要查）
- [ ] 改完用什么验证？（自测/一致性/单测）已跑过吗？
- [ ] 我有没有把"内置记忆"当"事实"用？若有，标【待核验】并回退。

## 📥 反面案例库（真人真事，下个 AI 务必先读）
- **2026-08-03 · WorkBuddy · 模型优化误判**
  - 1. 断言 `deepseek-v4-pro` 无效 → 错。官方当前有效名是 v4-flash/v4-pro，旧 chat/reasoner 2026-07-24 停用。根因：未联网核验，凭内置记忆。
  - 2. 断言蒙特卡洛固定种子=必改 bug → 错。实际 `montecarlo.py` 默认 `seed=None`，固定种子仅一处且不影响结论。根因：未先 Read 真实代码。
  - 3. 直接改 `.git/hooks/pre-commit` → 错落点。钩子真源是 `tools/pre-commit-hook-wrapper.sh`，由 `install_hooks.py` 复制。根因：改前未查调用/生成链。
  - 4. 用户要求"全部核实过再动手"后才动手 → 正确流程。验证手段：`--self-test` 7 项 + `check_consistency.py` 8 项 + commit/push。
  - 关联: JS-20260803-01 / JS-20260803-02
- **通用教训**：AI 内置记忆会过时、外部 API 天天变。**"我看过的"才是事实，"我记得的"不是。** 动手前先核实，是对用户负责，也是避免把错误写进代码/文档污染后续所有会话。

3. 改动是否跑了对应验证（不是"应该没问题"）？
