# 金水谣 · UI 设计方案 v1（可落地版）

> 生成日期：2026-09-23
> 勘察范围：`Jinshuiyao_Fixed/`（142 HTML）+ `模型/` 同级前端（54 HTML）+ `config/` 7 份配置 + 五份规范文档
> 适用对象：金水谣 Web 端（`localhost:18888`，Python 标准库 HTTP + 静态 HTML 直出）
> 硬约束：**不引入前端框架与构建工具**（与现有栈一致），全部通过 CSS 变量 + 原生 JS + 渐进替换落地
> 品牌硬约束：七色体系不可变更、禁止第 8 色相（`金水谣_契.md` §五，且已被 `closeout_gate` 第 5 项门禁自动守着）

## 3. 关键页面布局与视觉层级

### 3.1 六种页面模板（Page Shell）

#### S1 门户型 `/`

```
┌───────────────────────────────────────┐
│ Hero：一句话价值主张 + 服务器状态提示条  │  ← 1 级：香槟金大标题
├───────────────────────────────────────┤
│ 三大本领（工具 / 知识库 / 数据库）3 卡    │  ← 2 级
│ 三步上手 3 卡                           │
│ 新手常问 FAQ                            │
│ 入口卡片网格（四大领域 + 日报）           │  ← 2 级：卡片标题香槟金
└───────────────────────────────────────┘
```
- 栅格：桌面 3 列 / ≤1024 转 2 列 / ≤768 转 1 列
- 视觉层级：Hero 标题 40px 香槟金 > 区块标题 24px 暖银白 > 卡片标题 20px 香槟金 > 正文 16px 暖银白 70%
- 保留现有 Hero + 三角色结构（**已验证有效，不重做**），仅统一到新 token

#### S2 Hub 型（`/lottery`、`/fund`、`/stock`、`/football`、`/control-center`）

```
┌───────────────────────────────────────┐
│ H1 领域名 + 一句话定位（含诚实性声明）   │
│ [分组标题] 核心工具                      │
│ ┌────┐┌────┐┌────┐  卡片：图标+标题+说明+标签 │
│ └────┘└────┘└────┘                     │
│ [分组标题] 进阶工具                      │
└───────────────────────────────────────┘
```
- 卡片最小高度统一 132px；标题 16px/600，说明 13px/暖银白 70%，标签 11px
- 彩票 Hub 必须在副标题常驻：**「工具性质，不预测中奖」**（合规红线）

#### S3 看板型（`/lottery/dashboard`、`/health-check`、`/scheduler` …）

```
┌───────────────────────────────────────┐
│ 页头：标题 + 最后更新时间 + [刷新]       │
│ KPI 行：4 个指标卡（数字 32px 冰水蓝）   │  ← 数字是最强层级
│ 主图表区（1 或 2 列）                   │
│ 明细表 / 状态列表                        │
└───────────────────────────────────────┘
```
- KPI 数字用**冰水蓝 32px/700**，单位 14px 暖银白 55%；状态色只用墨绿金/香槟金/赤铜三色点
- 图表一律套 `jinshuiyao-echarts-theme.js`（已存在，10 页在用）→ 提升到 100%

#### S4 工具型（缩水过滤、旋转矩阵、奖金计算、定投模拟）

```
┌─────────────────┬───────────────────────┐
│ 参数区（左/上）   │ 结果区（右/下）        │
│ 表单 + [运行]    │ 加载态→结果→空态/错误态 │
└─────────────────┴───────────────────────┘
```
- 桌面 340px 参数栏 + 自适应结果区；≤768 上下堆叠
- 结果区必须有 5 态：加载 / 成功 / 空 / 错误 / 免责声明（彩票类）

#### S5 对话型（`/ai-agent`、`/workbench`）

```
┌────────┬────────────────────────────┐
│ 侧栏    │ 消息流（用户右对齐/AI 左对齐）│
│ 分组    │ ─────────────────────────  │
│ 会话    │ 输入框 + [发送] + 状态提示   │
└────────┴────────────────────────────┘
```
- 侧栏 260px，≤1024 抽屉化；导航项**必须从 `<div onclick>` 改为 `<button>`**（键盘可达）
- 输入框固定底部，Enter 发送 / Shift+Enter 换行

#### S6 文档型（`/docs`、`/architecture` …）
复用视觉体系「场景四：浅底深字」——正文区可用浅底（暖银白背景 + 深海墨蓝文字）提升长文可读性，链接冰水蓝。

### 3.2 视觉层级通则

| 层级 | 手段 | 令牌 |
|------|------|------|
| 1 级（最强） | 大字 + 香槟金 / 冰水蓝数字 | `--js-fs-display` 40px / `--js-gold` |
| 2 级 | 区块标题 + 卡片容器 | `--js-fs-h2` 24px + `--js-card-bg` + 1px 金边 |
| 3 级 | 正文 | `--js-fs-body` 16px + `--js-ink` |
| 4 级（最弱） | 辅助说明 | `--js-fs-caption` 12px + `--js-ink-dim` |

> 规则：同一屏内**最多 1 个 1 级元素**；强调优先用字号/字重，其次用色，不叠加多种强调色。

## 4. 核心任务交互流程

### T1 一句话问 AI → 拿到结论（最高频）

| 阶段 | 界面行为 | 状态 |
|------|---------|------|
| 1 进入 | `/ai-agent`，光标自动聚焦输入框 | 默认 |
| 2 输入 | 输入中文需求；输入框随内容增高（≤5 行） | 输入中 |
| 3 发送 | 按钮变 loading（转圈 + 文案「思考中」），**禁用发送**，输入框保持可编辑 | loading |
| 4 流式返回 | 消息区逐字渲染，底部显示「▍生成中」 | loading |
| 5 完成 | 恢复按钮，落一条 Toast「已完成」，消息区追加「复制 / 重新生成」操作 | success |
| 异常 A 网络断开 | 顶栏健康灯转赤铜，消息区显示错误气泡 + 「重试」按钮，**不丢输入内容** | error |
| 异常 B 付费额度耗尽 | 提示「已达到今日额度上限，已切换免费模型」，结果照常给出但标注模型名 | warn（降级） |
| 异常 C 后端未启动 | 健康灯灰色 + 全屏错误态：「服务未启动，请双击 启动金水谣助手.bat」+ 一键复制命令 | error |

### T2 彩票工具：选彩种 → 过滤 → 出候选集

| 阶段 | 行为 | 状态 |
|------|------|------|
| 1 | Hub → 工具页，参数区默认填充上次选择（localStorage） | 默认 |
| 2 | 选彩种 / 设条件；**任一必填未填时「运行」为 disabled** | disabled |
| 3 | 点运行 → 结果区骨架屏，运行按钮 loading | loading |
| 4 | 出结果：候选集表格 + **「候选集·非购买建议」声明条**（常驻，不可关闭） | success |
| 5 | 可导出 / 复制 | success |
| 异常 A 数据过期（>3 天） | 结果区顶部黄色（香槟金）提示条：「数据更新于 X 天前，结果仅供参考」+ [立即刷新] | warn |
| 异常 B 条件过严无结果 | 空态：「没有符合的号码组合」+ 建议放宽条件 + [重置] | empty |
| 异常 C 抓取失败 | 错误态 + [重试]，保留已填参数 | error |

### T3 基金持仓风险巡检

| 阶段 | 行为 |
|------|------|
| 正常 | 仪表盘按 danger/warn/notice/safe 四档渲染状态点；规模 <0.5 亿=赤铜(danger)、<2 亿=香槟金(warn)、单季 ±≥100%/≤-30%=warn、经理 180 天内变更=warn、配置名不符=notice（**灰色小字，不占用警示色**） |
| 关键 | 限购额度与计划日投比较：低于日投 → 赤铜标记「定投执行不了」；「无限额」必须显示为「无限额」而非 0 |
| 异常 | 抓取失败 → 该卡片显示「暂缺」+ 上次成功时间，**绝不填 0 或占位数字**（诚实性红线） |

### T4 系统运维：一键运行 / 状态刷新

| 阶段 | 行为 |
|------|------|
| 正常 | 侧栏/顶栏健康灯实时；[一键运行] → loading → Toast 成功 |
| 降级 | 错误率 >10% → 健康灯转香槟金 + Tooltip 显示具体错误数 |

### T5 数据源异常排查（跨页通用）

2. 涉事页面 KPI 卡状态点变色
3. 结果区顶部**内联提示条**（不打断操作，不用弹窗）

### 5.2 ⚠️ 待拍板：两个「文字态派生色」

**问题（实测，非估计）**：墨绿金 `#2D8B7E` 在卡片底色上对比度 **3.62**，赤铜 `#C8755A` **4.36**，均**低于 WCAG AA 的 4.5:1**，作为小字文字不合规。

**方案 A（推荐）**：同色相提亮，新增两个**文字专用**派生变量（不新增色相，只是明度档）

| 令牌 | 色值 | 卡片底 / 主底对比度 | 用途 |
|------|------|------|------|
| `--js-jade-text` | `#3FA593` | **4.97 / 5.83** ✅ | 墨绿金文字 |
| `--js-copper-text` | `#D98B73` | **5.59 / 6.56** ✅ | 赤铜文字 |

| Modal | `role="dialog"` + `aria-modal="true"` + `aria-labelledby`；Esc 关闭；遮罩点击关闭；**打开时锁 body 滚动**；关闭后焦点回到触发元素 |

| 加载 | 短任务（<400ms）用按钮内联转圈；长任务用骨架屏；**禁止全屏遮罩阻断** |
| 空态 | 图标 + 一句人话说明 + 1 个主操作（如「放宽条件重试」） |
| 错误态 | 错误图标 + 发生了什么 + 现在能做什么（重试/回退）+ 错误码（折叠） |

## 8. 跨页面一致性原则（7 条）

1. **单一 Token 真源**：所有颜色/字号/间距/圆角只走 CSS 变量；页面内禁止硬编码色值（已有禁色门禁，建议再加"硬编码色值"检查项）。
2. **一套导航走天下**：顶栏 + 面包屑是唯一导航与返回机制；任何页面不得自定义第二套导航或自定义 back-link。
3. **模板优先**：新页面必须从 S1–S6 六种模板里选一个套用，不得自创布局；模板即一致性。
4. **组件不重造**：需要 Modal/Toast/表格/图表 → 先查 `_shared/`；没有才新建，新建必须进 `_shared/` 并登记。
5. **状态表达统一**：同一语义永远同一表现（成功＝墨绿金、警告＝香槟金、错误＝赤铜、进行中＝冰水蓝），禁止页面上自创"黄=警告、红=错误"。
6. **诚实优先于美观**：数据缺失写"暂缺"；彩票结论必带 disclaimer；不为了填充版面造数字。
7. **渐进不改坏**：新组件用 `jsy-` 前缀与旧样式并存；每改一页必须在该页自测（可视化 + Tab 键走查 + 断点收缩）后再合入。
