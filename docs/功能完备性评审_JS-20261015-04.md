## 零、评审口径与现状速览

### 0.1 先说"不评什么"（避免空泛设想）

本项目是**单用户、本机回环（127.0.0.1）、桌面 GUI + 本地 Web 双入口**的个人工具，**不是多租户 SaaS**。因此以下"常见能力"**明确排除**：

| 常见能力 | 排除理由 |
|---|---|
| 用户体系 / 登录 / 角色权限 / RBAC | 安全边界是"是否本机"（`router.py:874 _is_local()`，19 处写接口已用其守卫），引入账号体系纯属负担。**替代方案见 O-07：写操作二次确认** |
| 消息推送 / 邮件 / 短信 / WebSocket 服务端推 | 本地进程无推送通道，GUI 已有消息框 + 日志面板。**替代方案见 O-05：长任务进度反馈** |
| 埋点统计 | **已有**：`telemetry.jsonl`（5390 行）+ `/api/telemetry/dashboard` + `/api/frontend-errors` |
| 数据缓存 | **已建成**：`utils/cache_manager.py`（MemoryCache/FileCache/`@cached(ttl=)`）。缺的不是"有没有"，而是"有没有统一用" ⇒ **归为 O-08 收敛项，不是新建项** |
| 多语言 / 移动端 / 支付 | 与本项目无关 |

> ### ⚠️ 勘误（落地时实地取证发现，优先级高于上表）
>
> 上表第 1 行的缺口描述**不够准确**，实地取证后修正如下：
>
> | 项 | 原先判断（错） | 实测（对） |
> |---|---|---|
> | `/api/prediction/list` 是什么 | 「彩票预测列表」 | **AI 问答预测沉淀**，读 `predictions/predictions.json`，实测仅 **7 条**，字段为 `question/answer/domain/outcome` |
> | 3636 条彩票数据在哪 | 走该接口 | 在 `金水谣数据/predictions.json`，**没有任何列表 API 暴露它**，只在后端内部被统计/命中率函数读取 |
> | web 端「预测追踪」页显示什么 | 彩票预测 | 调 `/api/prediction/list` ⇒ **只显示 7 条 Q&A**，彩票预测一条都没有 |
>
> **结论：缺口比原判断更严重——3636 条彩票预测记录在 web 端完全查不到，只有 GUI 能看，而 GUI 还是一次性全量渲染。**
>
> **取证方式**：直接 `curl -X POST http://127.0.0.1:18888/api/prediction/list -d '{"limit":200}'`，返回 `total=7` 且记录字段为 `question/answer/domain/outcome`（无 `lot`/`period`/`nums`）。
>
> **本轮已据此补建** `GET /api/lottery/predictions`（见 §1.2 S-01/S-02），并保留 Q&A 接口的独立检索口径（字段为 `question/answer/domain/time`）。

### 1.3 体验细节（你点名的三类）

**（1）结果不准确 —— 三个真实成因，别只改文案**

| 成因 | 实证 | 对策 |
|---|---|---|
| 检索范围过窄 | `static.py:724` 的 `q` 只匹配标题+标签，正文不参与 | 扩到正文（S-05），但**标题/标签加权**保证相关性 |
| 号码格式不统一 | 「01 02 03」与「010203」互不相认 | 号码走**结构化集合比对**，不走子串（S-09） |
| 静默降级被当成"没结果" | AI 链路失败返 `""`（`ai_service.py:718-720`），调用方若未判空就显示空列表 | 检索失败必须**显式报错**，不可退化为空结果 |

> 最后一条是本项目最有价值的一条：它和 10-12 那次「门禁误杀伪装成数据陈旧」、以及今早「自动同步 FATAL 伪装成任务在跑」是**同一个病**——**静默失败伪装成正常状态**。

**（2）条件回显** —— 见 S-07。补充两条硬要求：
- 分页、排序、筛选三者**状态必须一起保持**，翻页后条件不能丢、排序不能复位。
- 返回列表页时恢复上次条件（web 走 URL，GUI 走实例状态），否则用户每次都要重设。

**（3）空结果提示** —— 见 S-08。关键是**区分三态**并各给出口，而不是统一"暂无数据"。
