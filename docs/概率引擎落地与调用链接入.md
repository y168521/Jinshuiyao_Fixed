## 一、背景

`engines/lottery_probability.py`（487 行）作为「概率工程 50 讲」的闭式解引擎早已建成，
配套 25 条单测（提交 496b51f）。但它一直**躺在仓库里没接电** —— 全仓除了它自己的测试，
没有任何业务调用点。孤立的能力等于没有能力。

本次把它接入 `prediction_service.generate()`，让**每一次预测都携带理论随机基线**。

## 三、本次接线

### 新增（模块级函数，含 AST 闸防孤立）

`engines/prediction_service.py::get_probability_baseline(lot)`

```python
probability_baseline = get_probability_baseline(lot)   # 在 generate() 成功分支内
return {..., "probability_baseline": probability_baseline}
```

返回结构：

```python
{
  "ok": True,
  "lot": "大乐透",
  "sample_space_total": 21425712,
  "jackpot_prob": 4.667e-8,
  "expected_front_hits": 0.714286,     # n*K/N = 5*5/35
  "at_least_one_front_prob": ...,
  "win_any_prize_prob": {...},          # 来自 prize_rules 单一真源
  "honest_note": "公平随机模型下的理论值…本引擎只描述随机结构，不预测、不荐号"
}
```

不支持的彩种 / 规则缺失 → `{"ok": False, "reason": ...}`，**绝不抛异常打断预测生成**。

### 为什么用 AST 闸

单测里加了 `TestBaselineWired::test_generate_calls_baseline`：用 AST 解析
`prediction_service.py`，断言 `generate()` **确实调用**了 `get_probability_baseline`
且返回值含 `probability_baseline` 键。

理由：本轮主题就是「写了却没人调用」的静默失效（`refresh_history` 全仓 0 调用点）。
一个 helper 存在 ≠ 它被接进链路，这道闸把「孤立 helper」变成编译期可见的红灯。

## 四、适用场景（能做什么）

1. **说明真实难度** —— 看板/报告展示头奖 1/21425712、理论总中奖率，让用户对彩票建立正确认知。
2. **对照基线** —— 拿系统实际命中率与理论值并列展示。若两者接近即诚实得出「无预测力」，
   这正是 `DEGRADED_LOTS` 已标注的结论（双色球/大乐透/七星彩）。
3. **复式收益核算** —— `expected_front_hits`、各奖级概率可用于算期望收益与返奖率。

## 五、边界与禁止事项（诚实红线）

| 禁止 | 原因 |
|------|------|
| ❌ 把基线与 SQI / 置信度混为一谈 | SQI 只反映信号清晰度与数据质量，**不是中奖概率** |
| ❌ 渲染成「中奖率提升」 | 基线是"瞎猜也能达到的水平"，与本系统能力无关 |
| ❌ 用 pmf 反推"该买什么号" | 均匀分布下每个号码概率完全相同，引擎文件内含 `honest_note` 明令禁止荐号 |
| ❌ 在别处重写一份概率口径 | 违反 MEMORY 铁律「同一业务含义锁定同一数据端点」 |

`win_any_prize_prob` **必须**走 `utils/lottery_prize.load_rules()` 单一真源 ——
此前奖级表散落四处（含前端硬编码）已造成过 8 个月误判（JS-20261002-15）。
概率引擎不自己存奖级表，就是这个原因。
