# 视觉 L2 禁用色根治 · 架构设计（JS-20260728-18）

> 道衍推导：阳=机器扫色+改（显性能力）；阴=守底（只改明确禁用饱和色，不误伤中性灰/业务蓝）。
> 知止：默认只自动改写 FORBIDDEN_MAP 命中的禁用色，off-theme/中性色仅报告不擅改。

## 一、PRD（产品经理 · 许清楚）

- **问题**：owner 默认主题（L2）禁用 `#ef4444`/`#22c55e`/`#eab308`/`#8b5cf6`/`#f97316`。
  今日知识体检 + 人工扫发现：①`scripts/daily_fund_monitor.py:556-561`、②`tools/run_tests.py:540-541`
  两处生成器源码硬编码禁用色；③已生成的 4 份 `金水谣数据/fund_reports/*.html` 带禁用色。
  而收工门禁 `[F] 禁用色合规` 因**故意排除 `金水谣数据`（自动报告目录）**且**只扫 `.html/.css` 不扫 `.py`**，
  未能拦住——这正是今日违规漏网的根因。
- **范围**：根治生成器（2 个 `.py`）+ 清理已生成（4 份 HTML）+ 收紧门禁覆盖范围。
  不动任何业务逻辑、零新依赖、不改功能。
- **验收标准**：
  1. `daily_fund_monitor.py` / `run_tests.py` / `fund_reports/*.html` 不再含 5 个禁用色（含 rgba 形式）；
  2. `closeout_gate.py [F]` 能覆盖 `fund_reports` 并检出故意注入的禁用色；
  3. `py_compile` 三个源文件全过；
  4. 零功能回归（仅颜色字面量变更）。

## 二、架构（架构师 · 高见远）

- **单一真源**：复用 `core/agent_theme.py` 的 `FORBIDDEN_MAP`（与「AI 配色扫雷」「[F] 门禁」同一标准，判定一致、可审计）。
- **替代色映射**（可见性优先，避免原 map 把紫色映射到过暗的 `#162840` 导致强调色不可见）：
  - `#8b5cf6`（紫/brand）→ `#C9A96E`（香槟金，L2 品牌强调色，深色背景可见）
  - `#22c55e`（正绿/up）→ `#2D8B7E`（墨绿金，正向）
  - `#ef4444`（正红/down/alert）→ `#C8755A`（赤铜，负向/报错）
  - `#eab308`（正黄）→ `#C9A96E`（香槟金，警告）
  - rgba 对应：`139,92,246`→`201,169,110`；`34,197,94`→`45,139,126`；`239,68,68`→`200,117,90`
- **T01** `daily_fund_monitor.py:556-561`：改 CSS 变量；`--brand-light:#a78bfa`（浅紫 off-theme）→ `#E8ECF1`（银白，与香槟金配渐变）。
- **T02** `run_tests.py:540-541` + 三处 rgba 形式（`139,92,246`/`34,197,94`/`239,68,68`）：改安全色。
- **T03** `closeout_gate.py [F]`：在 `SCAN_ROOTS` 增加 `金水谣数据/fund_reports`（外科手术式，**不动原 EXCLUDE 列表**），
  使门禁覆盖自动报告违规色，生成器一旦回归即被收工拦截。
- **T04** 4 份 `fund_reports/*.html` 就地用 `agent_theme.fix_colors` + rgba 替换清零（数据产物；未来由 T01 生成器保证新报告合规）。

## 三、风险与回滚

- **风险**：低。仅颜色字面量变更，不涉及逻辑；gradient / 图表 `itemStyle` 同步替换保证视觉一致。
- **回滚**：纯字符串替换，`git revert` 单提交即可；`py_compile` 兜底语法。
