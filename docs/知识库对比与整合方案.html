1 五个维度的主要区别

维度 你的 AI 知识库
(Jinshuiyao 用户知识库)		 Karpathy LLM Wiki
(2026-04 方法论)
定位 系统内部的问答/价值自动沉淀器，为预测引擎 + 代码助手的"闭环成长"服务。偏"记录留痕"。 个人/团队的知识编译与增长范式，把 AI 从"搜索引擎"升级成"知识编译器"。偏"认知增值"。
内容覆盖 目前主要是一问一答的卡片（代码问题、概念解释、复盘要点），单条独立、彼此不连。 原始资料（论文/文章/图片/会议记录）→ 摘要页 / 实体页 / 概念页 / 综述页 / 对比页，成体系。
结构组织 扁平单层：日期_标题.md 卡片 + INDEX.json 索引 + README。靠关键词相关度检索（中文2-gram，阈值0.8）。 三层分明：raw/(只读原料) → wiki/(AI维护的互链页面) → schema(CLAUDE.md 规则文件)。带反向链接与知识图谱。
目标受众 系统自己 + 你：主要给程序调用（问答前检索/答后归档），你偶尔翻看。 你 + 你的 AI Agent：人负责策展提问、AI 负责所有整理维护；用 Obsidian 实时浏览图谱。
更新维护 只增不理：新卡片追加 + 去重，但已有卡片不会被回头修订，也没有矛盾检查、没有孤岛清理。 三大操作循环：Ingest(摄入，一条资料触发10-15页更新) / Query(问答可反写回库) / Lint(定期体检：查矛盾、清过时、补缺口)。
核心差异一句话 你的库是"写完就锁"的账本（append-only）；Karpathy 的库是"边写边改、越改越顺"的活文档。 前者保证不丢、防污染；后者保证知识之间"打通"并持续进化。

2 各自优劣 & 可取长补短的点

✅ 你的库·优势

  • 纯标准库、零依赖：不用装任何东西，稳、轻、离线可跑。
  • 自动化沉淀：问答后自动归档 + 去重，不用你手动记。
  • 防浪费闭环：答前先查库、能免费答就不花 DeepSeek，已落地。
  • append-only 更安全：不会误改历史（这点其实优于 Karpathy）。

⚠️ 你的库·不足

  • 卡片互不关联，没有实体页/概念页，问复杂问题时拼不起来。
  • 只增不修：过时/错误卡片会长期躺着（"幻觉复利"隐患，见文末真实案例）。
  • 没有 Lint 体检，无人发现矛盾与孤岛。
  • 没有 raw 原始层，卡片即"结论"，无法回溯来源、难核对。

✅ Karpathy·优势

  • 知识"会长"：编译而非检索，越用越聪明，探索也能复利。
  • 三层+互链：概念/实体成网，复杂问题一次答全。
  • Lint 自我纠错：定期查矛盾、补缺口、清孤岛。
  • 社区火热：1500万浏览、多个开源实现、6条生产经验可抄。
  • 紧追前沿：Lint 会主动"建议下一步该研究什么"。

⚠️ Karpathy·不足

  • 依赖顶级大模型+人工参与，冷启动前5-10篇要你陪跑。
  • 会改历史：编译时若产生幻觉会被"刻进"库并强化。
  • 规模上限不明（约4000+笔记后遇瓶颈）。
  • 只是"想法文档"，没有现成代码，要自己搭。

逐维度"谁强谁弱 + 该向谁学"

维度你的库Karpathy取长补短方向
内容深度浅（单条问答）深（综述/概念页）向它学：加"概念页/综述页"，把零散卡片升华。
分类体系扁平标签三层+实体图向它学：引入 raw/wiki/schema 三层。
实用性已自动跑通要手搭你更强：把它的方法接到你现成的自动化上。
社区互动无全网热议向它学：抄社区6条生产经验（见下）。
前沿追踪被动Lint主动建议向它学：加"定期体检 + 建议新方向"。
安全/防错只增不改，稳改历史有幻觉风险你更强：保留 raw 只读 + append 日志，抵消它的风险。
可直接抄的"社区6条生产经验"（来自 Karpathy gist 评论区实战团队） ① 先分类再提取（大报告和短信件用不同流程，省 token）； ② 给索引设 token 预算（L0项目上下文/L1索引/L2搜索结果/L3全文，分级加载）； ③ 每种实体一个模板（人物页/事件页/文档页字段不同）； ④ 每个任务产出两份（一是答案，二是把发现回写进库）——这条最关键； ⑤ 第一天就设计跨域标签（frontmatter 加 domain）； ⑥ 人类做主编、只负责验证与抽查（AI 是作者，你是主编）。

3 具体整合方案：把两者优点合起来

思路：保留你库"自动化 + append 只增 + 零依赖 + 防浪费"的底子，嫁接Karpathy 的"三层结构 + 概念页 + Lint 体检 + 双输出"。分四步走，一步一个可验证成果，不推倒重来。

第一步 · 加 raw 原始层（最简单，先做）

在 knowledge/用户知识库/ 下新增 raw/ 目录，专放"原料"（你剪藏的文章、贴进来的资料、聊天记录）。规矩：raw 只读不改，卡片必须能回指到它的 raw 来源。

收益：结论可回溯来源，核对更放心；改动极小。

第二步 · 卡片升级为"三类页面"

把现在千篇一律的问答卡，按类型分成 摘要页 / 实体页（人物·工具·模块）/ 概念页，各用固定模板（对应社区经验③）。archive_knowledge.py 增加一个 page_type 字段即可，向后兼容旧卡。

收益：内容变有深度，复杂问题能拼得起来。

第三步 · 加 Lint 体检脚本（对抗"幻觉复利"）

写一个纯标准库的 lint_knowledge.py：定期扫库找 ①矛盾卡 ②过时卡 ③孤岛卡（无任何引用）④被反复提到却没独立页的概念 ⑤明显的测试垃圾（比如 DEEPSEEK_WAS_CALLED）。只报告、不自动删，你确认后再清。

收益：库不会变垃圾堆；正好堵住文末那个真实污染的口子。

第四步 · 落实"双输出" + schema 规则文件

在问答流程里强制"答完顺手回写库"（社区经验④），并在库根目录放一份 schema.md（相当于 Karpathy 的 CLAUDE.md）写清：目录结构、页面模板、归档与体检的规矩。让整个系统从"热心整理"变成"有纪律的维护"。

收益：知识真正开始"复利增长"，闭环从"看得见"进化到"会自己长"。
为什么这样接最划算 你已经有了 Karpathy 方案里最难自动化的那部分（自动归档 + 去重 + 检索）。缺的只是"结构 + 体检 + 双输出"这三块**加法**，都能用纯标准库补， 不用装向量数据库、不用 RAG（Karpathy 亲测：约100篇/40万字规模内，索引 + 摘要就够）。对你这种个人规模，性价比最高。

! 附：一个真实发生的"幻觉复利"案例（就在你库里）

上一轮我做"有密钥也不乱花钱"的验证时，用假函数替换了 DeepSeek 的返回值，但没把归档函数也替换成桩，结果假答案 DEEPSEEK_WAS_CALLED 被真的写进了你的知识库，污染了 2–3 张卡：

  • 20260718_问答：什么是闭包….md → 正文成了 DEEPSEEK_WAS_CALLED
  • 20260718_问答：登录函数为什么总返回_False….md → 同上
  • 20260718_问答：这段代码为什么会报错？.md → 验证残留 x = 1
这恰好印证了 Karpathy 说的头号风险："幻觉复利" 错误一旦进库，就会被当成"长期资产"反复复用、越滚越"可信"。这正是第三步 Lint 体检要解决的问题。
