## 一、要解决的问题：最危险的故障「不报错，只是停止进化」

智能大脑的学习链路是**分阶段落盘**的，三个阶段由不同进程/不同实例完成：

```
感知  采集开奖结果 → 复盘回写 predictions.json      （调度器定时任务 / GUI 手动复盘）
  ↓
推理  brain.learn_from_review → 更新 brain_state.json（数字偏差 / 方案权重）
  ↓
决策  生成预测时读取 digit_bias / strategy_weights    （prediction_service / domain）
```

只要任一环节没跟上，后面的环节就会**拿着旧状态继续跑**。表现是：
系统每天照常出预测、日志一切正常、没有任何报错，但它**再也没有变聪明**。

这类故障最难发现 —— 它不抛异常，只是静默地停止进化。本次把它从
「不可见」变成「可观测、可告警」。

### 本次定位到的两个真实缺口（均已修复）

| # | 缺口 | 后果 |
|---|------|------|
| 1 | `SmartBrain.refresh_history()` 有定义但**全仓 0 调用点** | 常驻单例大脑复盘后不重载历史，`self.history` 一直陈旧到进程重启 |
| 2 | `get_digit_adjustments()` 每次**从头重算并覆盖** `digit_bias` | `learn_from_review` 用**真实开奖号**算出的精确偏差，被用 `hits` 估算的重算结果覆盖 → 学习成果当场作废 |

## 二、三层链路定义

| 层 | 职责 | 落盘产物 | 主要执行者 |
|----|------|----------|-----------|
| 感知 | 采集开奖结果、复盘回写 | `predictions.json` | scheduler `_task_auto_review` / `LotteryDomain.review()` |
| 推理 | 从复盘中学号码偏差、方案权重 | `brain_state.json` | `SmartBrain.learn_from_review()` |
| 决策 | 用学到的偏差/权重生成预测 | 预测输出 | `prediction_service.generate()` |
| 知识 | 复盘统计提炼为引擎挂钩经验卡 | MiroFishDB 知识卡 | `strategy_cards.refresh_strategy_cards()` |

## 三、失配与陈旧检测（probe_linkage，只读探测）

新增模块：`engines/self_iteration.py`
探针函数：`probe_linkage(brain, data_dir=None, knowledge_cards=None)` → `LinkageStatus`

### 判定口径

| 指标 | 计算方式 | 含义 |
|------|----------|------|
| `learning_lag` | 已复盘记录数 − 大脑已学习记录数 | >0 ⇒ 感知到了新数据、推理没跟上（链路失配） |
| `decision_stale` | `predictions.json` 比 `brain_state.json` 新 | ⇒ 决策会用到旧学习状态（链路失配） |
| `knowledge_stale_days` | 知识卡 `last_updated` 距今天数 | > 30 天 ⇒ 知识陈旧 |
| `mismatch_detected` | 以上任一成立 | 链路失配总开关 |
| `spin_risk` | `learning_lag > 10` | 不是偶发落后，而是**持续落后** ⇒ 系统已停止进化 |

### 阈值（模块级常量，可被引擎/闸门校验）

```python
LEARNING_LAG_SPIN_THRESHOLD = 10   # 学习滞后超过此值 → 判定为反复空转
KNOWLEDGE_STALE_DAYS        = 30   # 知识卡超过此天数 → 判定知识陈旧
```

探测**只读**，绝不修改任何数据；读不到文件一律降级为 0/None，绝不抛错中断。

## 四、自我迭代编排（run_self_iteration）

`run_self_iteration(data_dir, review_fn=None, knowledge_refresh_fn=None)` 四个阶段：

1. **感知/采集** —— 调用 `review_fn()` 做复盘回写（由调用方注入，复用调度器口径，本模块不重复实现）
2. **推理/刷新** —— 重建 `SmartBrain` + `refresh_history()`，载入最新学习成果
3. **知识更新** —— 调用 `knowledge_refresh_fn()` 提炼知识卡
4. **闭环验证** —— 再次 `probe_linkage`，输出 `before` / `after` 状态，确认闭环是否闭合

任一阶段失败**降级继续**并记录 `*_error`，绝不让编排整体崩掉。

## 五、接线点

| 位置 | 接线内容 |
|------|----------|
| `engines/smart_brain.py` | 新增 `_ensure_fresh()`：决策前比对文件 mtime，自动重载 `history`/`state`（**跨实例自愈**，长生命周期单例无需外部手动刷新） |
| `engines/smart_brain.py` | `get_digit_adjustments()` 优先复用复盘学到的 `digit_bias`（缺号补 1.0），不再重算覆盖 |
| `engines/smart_brain.py` | `learn_from_review()` 末尾调 `refresh_history()` + 维护 `learned_review_count` |
| `engines/smart_brain.py` | `assess_confidence()` / `get_strategy_weights()` 决策前先 `_ensure_fresh()` |
| `core/infra/scheduler.py` | `_task_auto_review` 学习后 `refresh_history()` + `probe_linkage` 探测，把失配打到日志 |
| `domains/lottery/domain.py` | `review()` 学习后 `refresh_history()`（常驻单例场景） |
| `launch_jinshuiyao.py` | 新增 `_boot_self_iteration()`：开机后台线程触发一次自动复盘 + 链路探测，结果打印到启动日志 |

### 开机自动复盘的实现说明

调度器原本已把 `auto_review` 注册为 `run_now`（开机补跑，延迟 420s）。
本次在启动链路**显式**补一次：`get_scheduler().run_once("auto_review")`。
该任务**幂等**（只处理未复盘记录），与调度器自身的开机补跑不冲突。

## 七、诚实约束（不可逾越）

本模块只做**记账式**的链路检测 —— 「有没有学到最新的数据」。
它**不对「预测准不准」作任何判断**。

彩票本质上是随机事件，系统能承诺的只有：

- ✅ 学全了、没停摆（本模块保证）
- ❌ 学了就更准（**不承诺，也无法承诺**）

`DEGRADED_LOTS` 已标注双色球/大乐透/七星彩无预测力，SQI 只反映信号清晰度与数据质量，
不是中奖概率。任何页面不得把「闭环已同步」渲染成「中奖率提升」。

## 八、已知边界

- `_ensure_fresh` 依赖文件 mtime：若两文件在同一秒内连续写入且 mtime 精度不足，可能漏检一次；对每日级复盘场景无影响。
- `probe_linkage` 的 `learning_lag` 基于 `learned_review_count` 计数，仅当复盘走 `learn_from_review` 才准确；手工改数据不会计入。
- 开机自迭代线程固定延迟 60s 再触发，以确保调度器已完成任务注册；首次启动（尚未注册）会降级为「不触发」，由调度器自身的 `run_now` 兜底。
