## 2. 增量设计

### 2.1 决策卡字段 Schema（10 既有 + 3 新增并存）

**既有 10 必填（保留，自由文本）**：属主 / 做了什么 / 为什么根因 / 验证 / 坑 / 有效方法 / 关联文件 / 关联总索引 / **反事实对照**（通用设问）/ **置信度**。

**新增 3 结构化字段（ADDITIVE，与既有并存）**：

| 字段 | 适用 | 内容 | 取值约束 |
|------|------|------|----------|
| `counterfactual_baseline` | 预测/彩票类**必填** | 随机基线对照。优先取自 `montecarlo.random_baseline_rate`；或显式 `{rate, n, method}` | 文本+可选数值；含数值须可解析为基线率（禁纯"随机"空话，AC-2） |
| `baseline_comparison` | 预测/彩票类**必填** | 相对基线增量/结论；`gain≈0` 须明示"非模型能力" | 非空文本 |
| `honesty_note` | 预测/彩票类**必填** | 诚实免责 | 必含关键词之一：**随机 / 无法保证 / 运气 / 幸存偏差** |

**头部 schema 说明更新**（ai_decisions.md 第 8–11 行）：在"必填字段"段补一句——"预测/彩票类卡另须含结构化三字段 `counterfactual_baseline`/`baseline_comparison`/`honesty_note`（与既有'反事实对照'并存：前者结构化机检、后者通用设问）；旧卡缺新字段不算非法（祖父条款）。"

### 2.2 知识卡附加字段（同步）

auto_knowledge 抽取 Layer B 知识卡时，对预测/彩票类卡**透传**上述三字段（沿用现有 `category`/`tags` 机制，不改抽取主流程）。即：抽取函数遇到触发标签时，把三字段写入卡片 frontmatter，供后续检索/前端展示。AC-4 要求 `extract_*` 不抛错——新字段为**可选透传**，旧卡无此字段时正常跳过。

### 2.3 标签触发常量（集中定义）

`scripts/closeout_gate.py` 顶部新增：
```python
# 触发"须填反事实三字段"的标签/关键词（与 auto_knowledge 预测类关键词对齐）
COUNTERFACTUAL_TRIGGER_TAGS = {"彩票", "预测", "预测摘要", "lottery", "prediction"}
def _is_counterfactual_scope(body: str) -> bool:
    return any(t in body for t in COUNTERFACTUAL_TRIGGER_TAGS)
```
[C] 检查对 `today_cards` 中 `_is_counterfactual_scope(b)` 为 True 的卡，追加三字段断言。

### 2.4 `check_counterfactual(rep)` 设计（供 [C] 调用）

抽自 `check_today_card()` 的小函数，入参 `(body, header)` 或 `(rep, header, body)`，对预测/彩票类卡执行：
- **AC-1**：`counterfactual_baseline` 非空（子串命中字段名且其后有内容）→ 否则 `rep` 记 `warnings`（告警，fail-safe，不计入 `incomplete`）。
- **AC-2**：若含数值基线，须可解析为基线率（正则提取数字/百分比）；纯"随机"空话无数值 → 告警。
- **AC-3**：`honesty_note` 必填且含诚实关键词之一（随机/无法保证/运气/幸存偏差）。
- **祖父条款（AC-5）**：旧卡（无可判定创建日期或在阈值前）缺新字段**不报错**；仅对本次新增/今日卡强制。
- **AC-4**：函数纯读取解析，不调用 auto_knowledge，旧 8 字段卡解析不受影响。

### 2.5 门禁 [C] 扩展接入点

`check_today_card(today_dash)`（第 127 行）：
- 现有逻辑（遍历今日卡、查 `REQUIRED_FIELDS`）保留。
- 在今日卡遍历循环内，对每张 `_is_counterfactual_scope(b)` 为真的卡：调用 `check_counterfactual(...)` 把三字段缺失并入 `rep["warnings"]`（fail-safe 告警，不并入 `incomplete`、不翻转 `all_ok`、退出码保持 0），与既有 [C] 报告统一呈现。
- `ok = not incomplete` 不变 → 三字段缺失仅让 [C] **告警（warn-only，fail-safe）**，不翻转 `all_ok`、退出码保持 0（AC-1/AC-3）；AC-2 数值解析失败同理计 `warnings`。
- docstring "8 字段"→"10+3 字段（预测/彩票类增三结构化字段）"修正。

### 2.6 提示词铁律 + 注入（T03）

**AGENTS.md 新增铁律**（建议插入第 12 行后、第 14 行"代码审查 Pipeline 铁律"前，与②风险登记册⑦并列）：
```

>    并填结构化三字段 counterfactual_baseline（优先取基线率，禁纯"随机"空话）/
>    baseline_comparison（gain≈0 须明示"非模型能力"）/ honesty_note（含 随机/无法保证/运气/幸存偏差 之一）。

```

## 6. 共享知识（跨成员须知）

- **诚实结论固化**：彩票/预测类增益≈0 = 运气/幸存偏差，**非模型能力**——三字段把它从自由文本升为机检结构，根治"成功就觉得自己英明"偏差。

- **数据源唯一**：`counterfactual_baseline` 首选 `montecarlo.random_baseline_rate`，保证基线率口径一致、可复现。
- **与②风险登记册协同**：预测/彩票类"运气偏差"属内部认知风险，可在后续 R-00x 入册（本次不建）。
