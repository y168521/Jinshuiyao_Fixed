## 3. 设计

### 3.1 契约欺骗修复（诚实标记，非破坏）
- `_record_sync(self, operation, success, detail="", reserved=False)`：record 增加 `"reserved": reserved` 字段。
- 4 个 stub 在线分支改为：
  ```python
  logger.info("分析数据上报：预留接口，未实现，安全跳过（诚实标记）")
  self._record_sync("report_analytics", False,
                    "reserved: 预留接口未实现，已安全跳过（非成功、非失败）",
                    reserved=True)
  return True
  ```
- **为何保留 `return True`**：①离线队列 `process_offline_queue`（1159）把 `False` 当「失败」计入 `result["failed"]` 并写 error——预留接口不该被标失败（它没失败，只是 intentionally 未实现）；②`return True` 表示「该操作已被处理/ack，无需重排」，是队列语义而非「同步成功」语义。用户可见的诚实性由 `sync_history` 的 `reserved=True` + 诚实 detail 承载：`get_sync_status()` 返回后看板可据 `reserved` 区分「真成功」与「预留跳过」。
- docstring 同步修正：方法返回语义从「是否同步成功」改为「是否处理（ack）；预留接口返回 True 表示已作为 no-op 安全处理，history 标记 reserved 非成功」。
