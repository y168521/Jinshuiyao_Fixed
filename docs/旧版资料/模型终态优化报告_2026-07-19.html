✅ 结论：模型已整体优化完成、垃圾文件已清理、全部核心功能实测可用。

之前"反反复复打不开"的真正根因不是优化没做，而是 旧的服务器进程一直占着端口、没加载最新代码，加上两个接口的解码/路径小缺陷。本次一次性把这三层都堵死，并清掉所有测试残留与缓存。

🔧 一、本次修复了什么

问题根因处理状态
功能时好时坏系统里漂着 7 个旧的 python 孤儿进程（含 4 个旧 guide_server + 3 个测试服务器），旧进程不认识新接口全部Kill；并强化启动器：双击 启动金水谣助手.bat 会先自动杀掉占用 18888 的旧进程再起最新版已解决
问答接口偶发 500/api/ask、/sync-api/task 等读取请求体时用了不带容错的 UTF-8 解码，遇到非纯 UTF-8 输入直接崩溃统一改为 decode('utf-8', errors='replace')（与全站其他接口一致）已解决
代码助手报"目录不存在"/api/ask 需指定代码目录，空路径时直接报错空路径时默认指向项目根目录，现在能正常回答已解决
分不清后端是否最新顶栏只看"通不通"，旧进程顶着端口也显示绿灯后端自带 version；前端发现无版本号即红字提示"后端版本过旧，请重启"已解决
