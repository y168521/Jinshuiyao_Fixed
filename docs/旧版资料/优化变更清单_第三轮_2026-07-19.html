二、安全与并发修复

#文件问题修复
1 core/circuit_breaker.py TOCTOU 竞争：can_execute() 先调用 self.state（获取+释放锁），再获取锁检查状态。两次锁获取之间另一个线程可能触发熔断，导致本应被拦截的请求放行。 Lock() → RLock()（可重入锁）；can_execute() 重构为单次锁获取，内联 OPEN→HALF_OPEN 状态转换检查。
2 server/utils.py
(原 guide_server.py)		 SSRF DNS 重绑定：_is_safe_http_url() 在验证时解析 DNS，但实际 HTTP 请求时再次解析。两次解析之间 DNS 记录可能变更（DNS rebinding 攻击），指向内网 IP。 增加二次 DNS 解析验证：要求两轮解析结果的 IP 集合完全一致才放行，阻断 TTL=0 旋转攻击。
3 server/handlers/health.py
(原 guide_server.py)		 GET 触发状态变更：/api/ai/mode/set 通过 GET 请求即可切换 AI 模式（online/offline）。浏览器预取、搜索引擎爬虫等可能意外触发模式切换。 将 /api/ai/mode/set 从 _do_GET_impl 移到 _do_POST_impl。GET 请求返回 405 Method Not Allowed。
