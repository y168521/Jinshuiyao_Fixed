二、严重问题 (Critical)

C-01 API 密钥明文暴露在云同步目录中

位置：Jinshuiyao_Fixed/deepseek_key.txt

问题：DeepSeek API 密钥（sk-f9fa6ea5...）以明文存储在坚果云同步目录中。虽然 .gitignore 已声明忽略此文件，但坚果云同步不受 gitignore 控制——该文件会被同步到所有设备的云端副本。任何有权访问该云目录的人都可以获取密钥。

修复方案：
  1. 立即将密钥迁移到 ~/.jinshuiyao-secrets/deepseek_key.txt（代码已支持从此路径优先读取）
  2. 删除项目目录中的 deepseek_key.txt
  3. 在 DeepSeek 控制台重新生成密钥（旧密钥可能已泄露）
  4. 在 .nutstoreignore 中添加 *secrets* 规则
C-02 requirements.txt 严重不完整

位置：Jinshuiyao_Fixed/requirements.txt

问题：当前仅列出 5 个依赖，但项目实际使用了至少 12 个第三方包。缺失的依赖包括：

此外，所有已列出的依赖都只用了 >= 最低版本约束，没有上限，未来 pandas 3.x 等可能破坏兼容性。

修复方案：补全 requirements.txt（见后文"补充文件"章节），并添加版本上限约束。
C-03 guide_server.py 单文件 1758 行，职责过重

位置：Jinshuiyao_Fixed/guide_server.py

问题：这个文件同时承担了 HTTP 路由、AI 聊天处理、知识管理、预测记录、文件服务、健康检查、自检、自动审计等 55+ 个路由的职责。任何修改都可能引发连锁问题，且无法独立测试各个功能模块。

修复方案：拆分为以下模块：
  1. server/router.py — 路由分发
  2. server/handlers/ai.py — AI 聊天/路由相关接口
  3. server/handlers/knowledge.py — 知识库 CRUD
  4. server/handlers/prediction.py — 预测记录与查询
  5. server/handlers/health.py — 健康检查与自检
  6. server/static.py — 静态文件服务

H-02 无项目打包方案（缺少 setup.py / pyproject.toml）

项目完全依赖 sys.path 操纵来解析模块导入，无法通过 pip install 安装。这导致：部署依赖手动复制目录、无法声明正式依赖关系、IDE 自动补全经常失效。

修复方案：创建 pyproject.toml（见后文"补充文件"章节）。
H-03 端口冲突风险

DeepSeek 助手默认端口 18890 恰好落在 guide_server 的回退端口范围（18888–18893）内。如果 guide_server 占用了 18890，DeepSeek 助手将启动失败。

修复方案：将 DeepSeek 助手端口改为 18900（远离 guide_server 的回退区间），或在 guide_server 的端口分配表中预留 18890。
H-04 run_tests.py 中 10+ 个测试文件映射已失效

FILE_CATEGORY 字典中引用的 test_safe_json、test_health_check、test_watchdog、test_evolution、test_plugin_manager、test_sync_manager、test_audit、test_smart_brain、test_auto_systems、test_creator_domain 在 tests/ 目录中均不存在。

修复方案：清理 FILE_CATEGORY 映射，只保留实际存在的测试文件；补充缺失的测试用例。

四、中优先级问题 (Medium)

M-01 程序操作步骤/ 中的部署文档描述的是旧系统

程序操作步骤.txt 和 最终版步骤.txt 描述的是"十二穹武 TS-QW V20.2"单文件系统的部署方式，与当前 Jinshuiyao_Fixed 多模块架构完全不同。按照这些步骤操作将无法部署当前系统。

M-02 Python 版本混乱：3.8 / 3.10 / 3.14 三套文档共存

系统实际运行在 Python 3.8（D:\python38），但 docs/ 中同时存在 3.10 升级指南和 3.14.6 安装指南。3.10 升级未完全完成，3.14.6 是一个当前尚不存在的 Python 版本。launch.bat 中搜索了 7 个候选路径，但实际只有一个有效。

M-03 重复文件：startup_selfcheck.py 存在两份

项目根目录和 工具与诊断/ 目录各有一份 startup_selfcheck.py，内容可能不同步。应以根目录版本为准。

M-04 工具与诊断/run.bat 编码损坏（乱码）

文件包含的中文显示为乱码（GBK vs UTF-8 编码不匹配），且硬编码了 D:\python38\pythonw.exe，在任何其他环境下都无法运行。

M-05 字符串格式化风格不统一

项目中 f-string（f"...{var}..."）和 % 格式化（"...%s..." % var）混用，部分文件甚至在同一段落中混用两种风格。日志模块也不统一：guide_server.py 用 log()、main.py 用 logging.getLogger()、auto_audit.py 直接 print()。

M-06 足球预测仪表板未连接后端 API

jinshuiyao-dashboard/ 使用内嵌/模拟数据，没有像 jinshuiyao-quant-dashboard/ 那样通过 quant_server.py 连接真实后端数据。

M-07 audio_toolkit.py 的 timeout 参数未生效

_run_ffmpeg() 接受 timeout 参数但函数内部从未使用它。这意味着长时间的 FFmpeg 任务可能无限阻塞。
