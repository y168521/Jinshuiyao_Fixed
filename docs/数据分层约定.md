# 数据三层隔离约定（Data Three-Layer Isolation）

> 编号：JS-20260728-17（架构师：高见远｜产品经理：许清楚）
> 配套：本目录 `数据三层隔离_架构设计与任务分解.md`（设计 + 任务分解）、`_class.mermaid`、`_seq.mermaid`
> 范围：明确「活 / 副本 / 保险」三层物理边界与文件归属清单；对应 PRD-17-P0-1、PRD-17-P0-3、PRD-17-P1-3。

---

## 0. 一句话

**运行时数据按易变性 / 重要性 / 可重建性分三层物理隔离：活层运行时、副本层周期快照（派生）、保险层版本化真源（git + insurance/）。共享高频写文件经 `session_coordinator` 全局租约串行化；任何异常一律 `[G]` 告警降级，不阻断主流程。**

---

## 1. 三层物理边界

| 层 | 物理位置 | 写权限 | git 跟踪 | 丢失后果 | 失败姿态 |
|----|----------|--------|----------|----------|----------|
| **活层 Live** | `金水谣数据/`（运行时子目录与文件：`brain_state.json`、`predictions.json`、`log/ai_decisions.md`、`log/经验收集箱.md`、`knowledge/`、`lot_data/`、`users/`、`review/`、`fund_data/`、`stock/` 缓存等） | server / AI / 脚本（共享文件须先租约） | 否（运行时 json/log 已 `.gitignore` 排除） | 可接受（可重建 / 从副本回退） | fail-safe 告警 |
| **副本层 Replica** | `金水谣数据/backups/`（`<tier>/<rel_path_sanitized>/<YYYYMMDD_HHMMSS_NNNNNN>.bak`；已有 `gui/` 子目录） | **仅备份脚本**（`scripts/data_backup.py`） | 否（派生快照，`.gitignore` 加 `金水谣数据/backups/`） | 可接受（退化到保险层） | fail-safe 告警 |
| **保险层 Insurance** | `git` 真源（`.py` / `config/*.json` / `启动提示词.txt` / `AGENTS.md` / `docs/*`）+ `金水谣数据/insurance/`（决策卡 / 经验箱 / `risk_register` 快照归档） | 人类 / 受控流程（git commit、受控备份脚本）；**活层运行时代码只读** | 是（真源 / 文档 / insurance 归档） | 几乎不可接受（最终防线） | 受控写 + 强校验 |

> 副本层允许坚果云同步；活层**不**跨机实时同步（决策 #5，与 JS-20260728-05/09 衔接）。

## 2. 文件归属清单（按类）

### 2.1 活层（Live · 运行时）
- `金水谣数据/brain_state.json`、`predictions.json`、`correlation_matrix.json`、`reference_pool.json`、`risk_state.json`、`free_model_status.json`、`lottery_health_report.json`
- `金水谣数据/log/ai_decisions.md`（决策卡）、`金水谣数据/log/经验收集箱.md`（经验箱）
- `金水谣数据/lot_data/`、`users/`、`review/`、`fund_data/`、`stock/` 缓存等运行时子目录
- `knowledge/用户知识库/`（知识库 / 经验箱，共享高频写 → 须租约）
- 演示 / 补充 / 脱敏数据（`*_demo*` / `*_supplemented*`）→ 活层派生

### 2.2 副本层（Replica · 派生快照）
- `金水谣数据/backups/hourly/`、`daily/`、`weekly/`、`legacy/`（旧 `*.json.bak.0~2` 迁移归档）
- 由 `scripts/data_backup.py` 生成，**活层代码不直接写**

### 2.3 保险层（Insurance · 版本化真源）
- **git 真源**：`scripts/*.py`、`config/*.json`、`启动提示词.txt`、`AGENTS.md`、`docs/*` 架构稿 / PRD
- **运行时重要成果归档（受控脚本写、活层只读）**：`金水谣数据/insurance/`（决策卡 / 经验箱 / `risk_register` 快照）
- **保险层真源数据**：`金水谣数据/risk_register.json`、`jinshuiyao/data/matches_real.csv`（真实数据真源）
- 真实数据（`*_real*`）→ 保险层关注 / 真源；演示数据不污染

## 3. 写租约（Write Lease · PRD-17-P0-2）

对**共享高频写**文件，写前必须 `LeaseManager.acquire_for_write(rel_path, intent, wait_secs=30)`，写后 `release()`。
底层复用 `scripts/session_coordinator.py` 的 `acquire/release/heartbeat`（单一全局 CLAIM，
跨团队 / 跨会话串行化，直击「撞号 + 互删 + 悬空提交」事故）。

**租约清单（`LayerRegistry.LEASE_REQUIRED_FILES`）**：
- `金水谣数据/log/ai_decisions.md`（决策卡）
- `金水谣数据/log/经验收集箱.md`（经验箱）
- `金水谣数据/brain_state.json`
- `金水谣数据/predictions.json`
- `knowledge/用户知识库/`（知识库 / 经验箱）

> 非共享文件免租约，以保性能。新增共享写文件只需在 `LayerRegistry.LEASE_REQUIRED_FILES`
> 登记，**不改 `session_coordinator` 源码**。

---

## 4. 活层可写白名单（PRD-17-P0-3）

`LayerRegistry.is_live_writable(rel_path)` 判定活层运行时代码能否写某路径：
- 保险层路径（`insurance/`、git 真源、`.py`、`risk_register.json`、真实数据真源）→ **False + `[G]` 告警**（活层只读）
- 副本层路径（`backups/`）→ **False + `[G]` 告警**（仅备份脚本可写）
- 活层白名单内 / `金水谣数据/` 或 `knowledge/` 前缀 → **True**
- 其余未授权路径 → **False + `[G]` 告警**（不阻断主流程）

---

## 5. 副本备份与恢复（PRD-17-P1-1 / P1-2 / P1-4）

- **备份**：`scripts/data_backup.py` 的 `BackupManager.run_once()` 按频率档快照：
  - `hourly`（默认保留 24 份）：`brain_state.json`、`ai_decisions.md`、`经验收集箱.md`
  - `daily`（默认保留 7 份，大文件降频）：`predictions.json`、`knowledge/用户知识库/`
  - `weekly`（默认保留 4 份）
  - 旧 `*.json.bak.0~2` 首次运行经 `migrate_legacy_bak()` 迁移进 `backups/legacy/` 并保留原文件兼容期
- **manifest**：`金水谣数据/backups/manifest.json` 记录每快照 `{rel_path, tier, ts, sha256, mtime, size}`
- **自检**：`BackupManager.self_check()` 联动 `jinshuiyao_data_guard.check_jinshuiyao_data()`，损坏 / 缺失 → `[G]` 告警
- **恢复**：`scripts/data_restore.py` 的 `RestoreManager.restore(rel_path, point="latest")`，读 manifest 得期望 hash → 校验快照 sha256 → 占锁覆盖写活层 → 出 `RecoveryReport`。损坏 / 缺失 → `[G]` 告警 + `RecoveryReport(ok=False)`，不抛异常

---

## 6. 演示 / 真实铁律（PRD-17-P1-3 · 全局规则）

- 真实赛果 / 真实用户数据：命名含 **`_real`**（如 `matches_real.csv`），归保险层真源，不得被演示数据污染
- 演示 / 补充 / 脱敏数据：命名含 **`_demo` / `_supplemented`**（如 `matches_supplemented.csv`），归活层派生
- `LayerRegistry.classify_demo_real(rel_path)` 校验命名合规：返回 `real` / `demo` / `unknown`
- 新增数据默认走此规则，物理分文件 / 分目录

---

## 7. fail-safe 总姿态（PRD-17-P0-4）

隔离 / 备份 / 租约**任何异常一律降级为 `[G]` 告警**（写入 `金水谣数据/log/isolation_alerts.log`），
**绝不抛异常阻断主流程**（与①门禁去盲区一致）。

---

## 8. 共享文件改动约定（并发安全）

凡改高冲突共享文件，一律「已存在则跳过 / 仅追加」幂等：
- `.gitignore`：append `金水谣数据/backups/`（已存在则跳过）
- `AGENTS.md`：追加「数据三层隔离铁律」块（标题已存在则跳过）
- `金水谣数据/risk_register.json`：R-002 `mitigation_status` 由 `待落地(项④)` → `已落地`（已落地则跳过）
- `工作留痕总索引.md`：登记 JS-20260728-17（编号已存在则跳过）
