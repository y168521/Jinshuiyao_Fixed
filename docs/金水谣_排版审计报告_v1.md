## 二、P1 逐条详解（含可直接粘贴的改法）

### A. 段落 / 列表零间距 —— 垂直节奏塌陷 【最高性价比】

**取证**
- `jinshuiyao-guide/_shared/css/theme.css:61`
  ```css
  *, *::before, *::after { margin: 0; padding: 0; box-sizing: border-box; }
  ```
- theme.css 全文**没有任何** `p` / `ul` / `ol` / `li` 的 margin 恢复规则（已 grep 确认，0 命中）。
- 标题只给了下边距、没给上边距：`theme.css:139` → `h2 { font-size: 20px; margin-bottom: 12px; }`
- 全站 `padding-top` 仅 7 处、`p { margin }` 规则 0 处。

**后果**：正文段落彼此紧贴、标题吸附在上一段末尾。读者无法分辨「段」与「段」，长文（使用说明、日报、文档页）可读性显著下降。

**建议改动**（追加到 `theme.css` 基础重置之后，约 8 行）

```css
/* ── 垂直节奏基线（:where() 特异度为 0，页面自定义一律优先，零回归）── */
:where(.container, .wrap, .main-content, main) :where(p, ul, ol, dl, blockquote, pre, table, figure) {
  margin: 0 0 var(--js-space-12, 12px);
}
:where(p, ul, ol, dl, blockquote, pre, table, figure):last-child { margin-bottom: 0; }
:where(ul, ol) { padding-left: 1.25em; }
:where(li) { margin-bottom: var(--js-space-4, 4px); }
:where(h1, h2, h3, h4) {
  margin: var(--js-space-24, 24px) 0 var(--js-space-12, 12px);
  line-height: 1.3;
}
:where(h1, h2, h3, h4):first-child { margin-top: 0; }
```

| 项 | 值 |
|---|---|
| 涉及属性 | `margin` / `padding-left` / `line-height` |
| 推荐取值 | 块间距 12px（段落）· 24px（标题上）· 12px（标题下）· 4px（列表项） |
| 标题行高 | **1.3**（现 theme.css 未设，继承 body 1.7 → 大字号行距过松） |
| 选择器 | `:where(...)` 包裹，**特异度 0** |

**成本/收益**：1 个文件 8 行，58 页立即生效；因用 `:where()`，任何页面自己的 `p{margin:X}` 仍然胜出，**零回归风险**。

### B. 字号阶梯三真源冲突 + 层级倒挂

**取证**

| 来源 | h1 | h2 | h3 | body |
|------|----|----|----|------|
| `tokens.css` `--js-fs-*`（**引用量 0**） | 32 | 24 | 20 | 16 |
| `theme.css` 实际生效 | 28 | 20 | 16 | 15 |
| 页面实测（频次最高） | **20px（34 处）** | **15px（27 处）** | 14/15/16 各 6–7 处 | 14 |

- 全站 `font-size` 取值 **30 种**，其中 4 个半像素值：`12.5px` `13.5px` `11.5px` `14.5px`。
- **层级倒挂实证 1**：`jinshuiyao-guide/control-center.html:167` 桌面 h1 = 26px → `:601` 移动端 h1 = **20px**，与 theme.css 的 h2（20px）**同级**。
- **层级倒挂实证 2**：`金水谣助手门户.html:92` `.sec h2` = 21px，`:123` `.role h3` = **18px**，相差仅 3px；而正文 15px → h3/正文 也只差 3px。
- **层级倒挂实证 3**：`theme.css:138-140` h3(16px) − body(15px) = **1px**，肉眼不可辨。

**建议改动（分两步，先做零视觉变化的一步）**

**步骤 1 — 接真源，行为完全不变**（改 `theme.css:63-71, 137-140`）：

```css
body { font-size: var(--js-fs-body, 15px); line-height: 1.7; }
h1 { font-size: var(--js-fs-h1, 28px); }
h2 { font-size: var(--js-fs-h2, 20px); }
h3 { font-size: var(--js-fs-h3, 16px); }
```

> 回退值 = 现值，所以**改完视觉一模一样**，但令牌真源从此接上了。

**步骤 2 — 单独评审后再切换数值**（改 `tokens.css`，一次提交全站生效）：

| 令牌 | 现值 | 建议 | 理由 |
|------|------|------|------|
| `--js-fs-body` | 16px | **16px**（保持） | 中文正文 <16px 在 1366×768 笔记本上偏吃力 |
| `--js-fs-h3` | 20px | **18px** | 与 body 拉开 ≥2px 档差即可，20 会挤压 h2 |
| `--js-fs-h2` | 24px | **22px** | |
| `--js-fs-h1` | 32px | **28px** | 与现网 28px 一致，减少跳动 |
| `--js-fs-caption` | 12px | **12px**（下限，不再更小） | 已发现 11px 200 处、10px 15 处，属无障碍风险 |

**顺带收敛半像素**（约 12 处，可脚本批量）：
`12.5px→13px` ｜ `13.5px→14px` ｜ `11.5px→12px` ｜ `14.5px→15px`

### D. 表格在移动端顶破整页

**取证**
- 56 个页面含 `<table>`；全站仅 **45** 个文件出现过 `overflow-x`（且多数用于 `pre`，不是表格）。
- `theme.css:194` → `table { width: 100%; border-collapse: collapse; }`，**没有滚动包裹容器**。
- 散落硬约束：`min-width` 有 12 种取值（80 / 180 / 200 / 220 / 120 …），门户页 `:174` 还有 `.map .name { min-width: 230px }`。

**后果**：≤768px 时列被内容顶住，`width:100%` 失效 → **整页横向滚动**（卡片、侧栏一起横移），不是「表格内滚动」。

**建议改动**（追加到 `theme.css`，约 5 行）

```css
/* 表格兜底：窄屏时让表格自己滚，而不是顶破页面 */
:where(.table-wrap) { overflow-x: auto; -webkit-overflow-scrolling: touch; }
@media (max-width: 768px) {
  :where(.container, .wrap, .main-content) :where(table) {
    display: block; overflow-x: auto; white-space: nowrap;
  }
}
```

| 项 | 值 |
|---|---|
| 涉及属性 | `overflow-x` / `display` / `white-space` |
| 推荐取值 | `overflow-x:auto`；`white-space:nowrap`（仅窄屏，防止中文单元格折成竖排） |
| 后续 P2 | 给未引 theme.css 的表格页逐个补 `<div class="table-wrap">` 包裹 |

### E. 缺断词 / 换行保护（长串顶破窄屏）

**取证**：`word-break` / `overflow-wrap` / `word-wrap` 全站仅 **17** 个文件覆盖（143 页中约 12%）。
风险串：英文模型名（`claude-3-5-sonnet`）、基金代码、长 URL、连续数字。

**建议改动**（追加到 `theme.css` 的 `body` 规则，3 行）

body { overflow-wrap: break-word; }          /* 比 anywhere 安全，不压缩 min-content */

:where(p) { text-wrap: pretty; }             /* 正文避免末行单字 */
```
> `text-wrap:balance` 在不支持的浏览器自动忽略，属渐进增强，无回归。

@media (max-width: 1024px) { .grid-4 { grid-template-columns: repeat(2, 1fr); } }
@media (max-width: 768px)  { .grid-3, .grid-4 { grid-template-columns: repeat(2, 1fr); } }
@media (max-width: 480px)  { .grid-2, .grid-3, .grid-4 { grid-template-columns: 1fr; } }
```
`auto-fill + minmax` 顺带解决「卡片内容长短不一导致列宽不均」。

**落地状态（JS-20260924-04）：** 抽样验收发现比「跳变」更严重的根因——`.grid-2/.grid-3/.grid-4` 在 theme.css 中**缺失 `display:grid`**（仅 `.grid` 有），导致只用 `class="grid-N"` 的受管页（review-dashboard / control-center / showcase / knowledge-browser / automation-status / system-tools）全部塌缩成 block 渲染，中间档完全休眠。实际落地采用「固定阶梯」而非建议的 `auto-fill+minmax`（阶梯更可控、与 P2 容器宽度断点一致）：`theme.css` 改为 `.grid,.grid-2,.grid-3,.grid-4{display:grid;gap:16px}` + `.grid-N{grid-template-columns:repeat(N,1fr)}` + 子项 `min-width:0` 防 `1fr` 内容撑破横向溢出；architecture / global-plan 两页本地栅格升级为 1200/1024/768/480 四级（4→3→2→1）。验收：一致性 9/9 PASS、收工门禁禁用色 0、零原生对话框、控制符 0。

### H. 容器宽度 20+ 种，跨页跳动（P2）

**取证**：`max-width` 取值 20+ 种 —— 1200(38) · 1040(5) · 960(13) · 860(13) · 900(20) · 1000(10) · 720(8) · 1100(8) · 700(7) · 1400(7) · 920 · 500 · 1080 · 760 · 980 · 880 · 800 …
`theme.css .container` = 1040；门户 `.wrap` = 1040；**总控台 `.main-content` 无 max-width**（宽屏撑满，单行可达 120+ 字符，远超中文舒适行长 40–50 字）。

**建议**
```css
/* tokens.css 追加 */
--js-content-w: 1200px;      /* 标准内容宽 */
--js-content-w-narrow: 960px;/* 文档/长文 */

/* control-center.html .main-content */
.main-content { max-width: var(--js-content-w, 1200px); }
```

### I. 间距未落 4px 栅格（P3）

**取证**：`padding` 19 种取值，非 4 倍数有 `3px(63) · 5px(56) · 7px(29) · 9px(16) · 14px(65) · 18px(18) · 30px(44)`；
`gap` 有 `10px(67) · 14px(38) · 18px(21) · 9px(3) · 3px(3)`。
`tokens.css` 已定义 `--js-space-4/8/12/16/24/32/48/64`，**引用量 0**。

**建议（只收区块级，不收徽章级）**：
`gap:10→8` ｜ `gap:14→16` ｜ `gap:18→16` ｜ `padding:30→32` ｜ `padding:14→16`
`2/3/4/5px` 属徽章内边距，**保留不动**。约 150 处，需脚本分批 + 复核，收益中等 → 排 P3。

### J. px / rem 单位混用（P3 · 建议不动）

53 个文件用 rem（如 `workbench.html:72` `.95rem`、`:78` `.5rem .4rem`），其余全 px。
后果：用户改浏览器默认字号时，rem 部分缩放、px 部分不动 → 同页比例失衡，WCAG 1.4.4「放大 200%」不达标。
**建议**：统一成本远高于收益，**维持现状**，但新增代码一律 px（与 theme.css 一致）；rem 收敛列入长期债。
