## 2. 设计目标（硬约束）

1. **绝不丢数据**：任何写路径在拿不到锁时，必须降级为"无锁直写 + [G]告警"，**禁止**因锁失败而静默丢弃写入。
2. **最小侵入**：复用现有 `session_coordinator` / `safe_write_json`，不重写内核。
3. **契约对齐**：知识/业务数据写入不再注入 `_metadata.checksum`。
4. **fail-safe**：租约异常一律降级告警，不阻断主流程（与①门禁去盲区一致）。

### 3.2 新增 `utils/shared_write.py`（接线能力）
提供两个对业务无侵入的助手（内部 `sys.path` 注入 scripts 后 `import lease_helper`，复用 `LeaseManager` + `safe_write_json`）：

- `protected_write_text(rel_path, content, mode='w', intent=..., wait_secs=15)`
  - 优先 `acquire_for_write`；获取失败 → `[G]告警` + **无锁直写（不丢数据）**；成功 → 写（mode='w' 走临时文件+`os.replace` 原子；mode='a' 加锁后追加）→ `finally release`。
- `protected_write_json(rel_path, data, intent=..., wait_secs=15)`
  - 优先获取租约；成功 → `safe_write_json(rel_path, data, embed_checksum=False)` → `finally release`；失败 → 直接 `safe_write_json(..., embed_checksum=False)` 不丢数据。
  - 统一 `embed_checksum=False`，顺带满足契约。

> 关键安全决策：与 `LeaseManager.write_protected`（锁失败即跳过写）不同，本助手在**锁失败仍写**——因为共享文档/知识库写入是"不可丢"的，租约只是"尽力共识"而非"硬阻塞"。锁的价值是让正常情况下的并发写串行化、可被看板发现，而非阻断。

## 4. 并发安全论证
- **跨 AI 互覆盖**：全局 advisory lease（`.workbuddy/session_claim.json`）+ 30min 过期自愈 + 600s 快速接管（同机持锁进程已死立即接管）。正常短锁每次写前 `acquire`/`heartbeat` 刷新，互不阻塞；异常滞留可被接管，不死锁。
- **崩溃/并发丢数据**：`safe_write_json` 临时文件+`os.replace` 原子替换，写一半崩溃原文件不变；自动滚动备份（最多3份）兜底。
- **锁失败不丢数据**：3.2 助手在锁失败仍直写，杜绝"为锁丢写"。

## 5. 回滚预案
- 单文件级：全部走 `safe_write_json` 自动 `.bak.0~2` 备份，损坏可 `safe_load_json` 自动恢复。
- 逻辑回滚：本刀纯增量（加助手/补清单/换写入方式），`git revert <本commit>` 即可整体回退；`PROTECTED_REL` 多三条不影响既有逻辑。
- 契约回滚：`embed_checksum` 默认改 False 后，若某消费方意外依赖 checksum，可局部 `safe_write_json(..., embed_checksum=True)` 恢复，不影响全局。
