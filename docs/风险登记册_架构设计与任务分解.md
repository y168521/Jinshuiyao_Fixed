## 2. 增量设计

### 2.1 `risk_register.json` Schema（9 字段 + 元信息）

```json
{
  "_schema_version": "1.0",
  "_generated_note": "本文件为单一真源；风险登记册.md 由 scripts/gen_risk_md.py 渲染生成，禁止手工双写",
  "review_policy": {
    "cadence": "monthly",
    "lint_hook": "knowledge/用户知识库/lint_knowledge.py",
    "stale_days": 90
  },
  "risks": [
    {
      "id": "R-001",
      "description": "免费模型政策易变（下架/转收费/限流/上新）",
      "impact": "免费推理通道随时可能整体不可用，影响所有依赖免费模型的审查/抽取任务",
      "probability": "高",
      "impact_level": "高",
      "mitigation": "已落地 free_model_pool 四件套：①配置外部化(config/free_models.json，换模型=改清单不动代码) ②故障转移(call_ai_failover 逐个尝试) ③付费兜底(get_fallback_cfg/call_paid→DeepSeek) ④自动探活(health_check_all→金水谣数据/free_model_status.json，全挂写告警)；scripts/free_model_health_check.py 每日巡检",
      "mitigation_status": "已落地",
      "owner": "core/free_model_pool 模块",
      "early_signal": "free_model_status.json 出现 down/degraded；health_check 全挂告警；审查调用返回 ALL_FREE_DOWN",
      "last_review": "2026-07-27"
    }
  ]
}
```

**字段规则（供 verify 校验）**：
- `id`：唯一，格式 `R-\d{3}`，升序无空缺。
- `probability` / `impact_level`：枚举 `{高,中,低}`。
- `mitigation_status`：枚举 `{已落地,待落地(项④),待落地(项⑤/⑥),规划中}`（本次仅前三种）。
- `owner`：具体模块名/机制名，**禁止"待定"**。
- `last_review`：ISO 日期 `YYYY-MM-DD`；与 `review_policy.stale_days`（默认 90）比较，超期标红。
- `description`/`impact`/`mitigation`/`early_signal`：非空字符串。

### 2.2 初始 3 条完整条目（9 字段真实值）

**R-001 免费模型政策易变** — 见 2.1 示例，`mitigation_status=已落地`，`owner=core/free_model_pool 模块`。

**R-002 坚果云同步可能丢/覆盖文件**
- description：坚果云跨设备同步偶发卡顿/冲突，可能丢文件或把旧版本覆盖新版本（尤其并发写）。
- impact：业务数据/知识库/命门文档可能静默丢失或回退，且难追溯。
- probability：中；impact_level：高。
- mitigation：待落地——本地备份三层（活/副本/保险，属项④）+ git 版本化 + 依赖①门禁去盲区发现能力（check_jinshuiyao_data 守护金水谣数据强校验项）。
- mitigation_status：待落地(项④)。
- owner：备份机制(项④)。
- early_signal：auto_backup 异常日志；git status 出现意外删除；①门禁报金水谣数据强校验项缺失。
- last_review：2026-07-27。

**R-003 多 AI 会话并发互删**
- description：多会话/多 AI 接力并发写共享文件（总索引/决策卡/日志/MEMORY），无协调会互删互覆盖。
- impact：共享知识被并发改写或损坏，知识库空转/丢失。
- probability：中；impact_level：高。
- mitigation：待落地——会话租约 Lease(session_coordinator 已有锁，写前 acquire/写后 release) + 全局快照(属项⑤/⑥)；现状已有 session_coordinator 锁，缺全局快照。
- mitigation_status：待落地(项⑤/⑥)。
- owner：session_coordinator。
- early_signal：session_coordinator 看板显示他者占锁；文件 mtime 异常跳动；MEMORY/决策卡出现被截断。
- last_review：2026-07-27。

> R-004（彩票随机基线失稳）/ R-005（三元组损坏）留作 **P2**，本次不建。

### 2.3 md 生成方案（同源渲染）

新增 `scripts/gen_risk_md.py`（纯 stdlib）：
- 读 `金水谣数据/risk_register.json` → 渲染 `金水谣数据/风险登记册.md`。
- 渲染结构：标题 + 概览表（ID/概率/影响度/状态/owner）+ 每条详情（9 字段分节）+ 底部"本文件由 json 自动生成，请勿手工修改"声明。
- **铁律**：md 仅由该脚本生成，人工不双写；CI/收工自检可校验"md 与 json 内容一致"或"md 生成时间戳≥json 修改时间"。
- 可选：在 `gen_risk_md.py` 内复用 `verify_risk_register.py` 的校验，确保只渲染合法 json。

### 2.4 `verify_risk_register.py` 设计（极简 stdlib）

**入口**：`python scripts/verify_risk_register.py [--json] [--path 自定义]`；默认读 `金水谣数据/risk_register.json`。
**退出码**：0=通过；1=有错误（非法/缺字段/过期）；2=文件缺失。
**校验点**：
1. **合法**：`json.load` 成功，且为 dict、含 `risks` 数组。
2. **字段齐全**：每条含 9 字段；枚举字段值合法；`owner` 非空非"待定"；`id` 格式/唯一/升序。
3. **过期标红**：`last_review` 解析为日期，距今 > `review_policy.stale_days`(默认90) → 标红（计入 errors 或 warns，建议 errors 以确保被 Lint 捕获）。
4. （可选）`mitigation_status` 不在已知枚举 → 警告。
**复用**：`lint_knowledge.py` 的 `lint_risk_register()` 直接 `import` 本脚本的 `verify(path)` 函数（或 subprocess 调用），把结果并入 `LintReport.errors/warns`。

### 2.5 知识体检 Lint 接入点

在 `knowledge/用户知识库/lint_knowledge.py`：
- 新增函数 `lint_risk_register(rep: LintReport) -> None`：定位 `金水谣数据/risk_register.json`（路径 = `os.path.join(KB_DIR, "..", "..", "金水谣数据", "risk_register.json")` 或基于 `__file__` 上溯两级），调用 `verify_risk_register.verify()`，把 errors/warns 并入 `rep`。
- 在 `lint(kb_dir)` 末尾（返回前）调用 `lint_risk_register(rep)`。
- **不新建自动化**：每月1号触发由既有 WorkBuddy 自动化/scheduler 负责（符合"不新建自动化"镜像铁律）；本次仅把校验逻辑挂进现有 Lint。

### 2.6 `AGENTS.md` 铁律新增文案

插入位置：第 12 行（`⑥ 收工必存` 段末）之后、第 14 行（`⚠️⚠️⚠️ 代码审查 Pipeline 铁律`）之前，新增：

```
> ⑦ **风险入册**：所有外部易变依赖（免费模型政策/云同步丢文件/多AI并发互删等）须先入
>    `金水谣数据/risk_register.json` 风险登记册，再动手——不得裸奔。新增/变更外部依赖前先登记或更新条目，
>    降级方案落地后回填 `mitigation_status`；登记册由 json 单一真源生成 md，禁止手工双写。
```

> 注：原文称"五高铁律"，新增后实际为六条；保留"五高"措辞但顺延编号⑦，避免大改文档结构（与既有"五高铁律"称谓共存，仅作扩展）。若主理人要求改称谓为"六高铁律"，列为待确认。
