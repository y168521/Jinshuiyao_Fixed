## 一、一句话总览

**单进程 + 多线程**的本地桌面应用：`launch.bat` 自举 → `launch_jinshuiyao.py` 预检 → `server` 起 `ThreadingHTTPServer`（`127.0.0.1:18888`）→ 手写路由分发到 22 个 handler；GUI（Tkinter）是**独立进程**、与 server **无 HTTP 往来**，直连业务对象写盘。

```
launch.bat → launch_jinshuiyao.py（自举+预检+备份）
                    ↓
        server/__init__.py::main()  单进程
                    ↓
        server/router.py::GuideHandler（手写分发，22 handlers）
                    ↓
   ┌────────────┬────────────┬────────────┬────────────┐
   │ domains/   │ engines/   │ core/ai/   │ core/infra/│
   │ 业务编排层 │ 算法引擎层 │ LLM 接入层 │ 基础设施层 │
   └────────────┴────────────┴────────────┴────────────┘
                    ↓
        金水谣数据/（运行时数据，多数不入仓）

GUI（gui/main_window.py）独立进程 ──直连──→ engines/ + 金水谣数据/
```

## 五、勘察中发现的待确认项（**需你拍板**）

> 以下均为只读勘察所得，未做任何修改。其中 ①②是**对我既有记忆的更正**。

### ① `video_to_kb` 不是「全仓 0 调用点（孤儿）」——已接线但链路是断的
- 生产调用点 **1 处**：`server/handlers/knowledge.py:498` `from core.infra.video_to_kb import ingest_to_kb`（位于 `POST /api/video/ingest`，外层有 SSRF 校验(492) 与 `run_external` 硬超时(500)）。
- **但导入链断**：`core/infra/video_to_kb.py:55-56` 裸导入 `from video_extractor import VideoExtractor`（✅ 同目录）与 `from content_refiner import ContentRefiner`（❌ 实际在 `core/ai/`）。
- 根因：第 51 行 `_PROJECT_ROOT = os.path.dirname(_THIS)` 算出的是 **`core/`** 而非项目根（注释自称"项目根 Jinshuiyao_Fixed"，与实际不符），两者都不含 `core/ai`；全仓亦无他处把 `core/ai` 插入 `sys.path`。
- **推断**：以 `core.infra.video_to_kb` 方式导入时 `ModuleNotFoundError` ⇒ `POST /api/video/ingest` 运行期应会 500。**建议**：要么修 import（改 `from core.ai.content_refiner import ContentRefiner`），要么按「孤儿」判定摘除 handler 接线——二选一，请定。

### ② 「把 AI 超时推进到库层」——**该优化不存在，前提有误**
- 实测：`_http_call` 第 198 行**已经是** `urllib.request.urlopen(req, timeout=timeout)`，`_ais_try_free_first`(608) 传 `timeout=60` ⇒ **库层超时早已就位**。
- 我上一轮在 `brain_daily.py:173-179` 写的「真正停止工作需要库层超时，此处只是兜底」注释，**方向对但结论用错了场景**：实测 40s/次是**模型真实响应耗时**（<60s 上限，未被截断），不是缺超时。40s×3 ≈ 大乐透 124s，完全吻合。
- **结论**：此项应从待办中撤销，避免后人重复做。真正的遗留是：线程兜底(15s)触发后，后台那次请求仍会跑完约 40s（`daemon=True` 仅保证不阻碍退出）——**影响可控，建议维持现状**。
- 全网检索另有真实缺口：**DNS 解析不受 `urlopen(timeout=)` 控制**（需 `socket.setdefaulttimeout()`）；但那是**全局**设置，会波及本地 Ollama 探活(0.3s)与 server 监听，**风险大于收益，建议不做**。

### ③ `server/router.py:963` 异常文本未脱敏
- `self._send_json({"error": f"读取失败: {e}"}, 500)` —— 与该文件 82-88/535-549 的统一脱敏策略不一致，会回传文件系统路径等内部信息（虽然仅本机可达，风险低）。
- **建议**：改为固定文案 + 服务端 `logger` 留痕。属于顺手可修的小项。

### ④ `football_matches.json` / `risk_register.json` 未被 `.gitignore` 覆盖
- 二者是运行时产物却会入仓，与 `predictions.json`（已排除）处理不一致。
- **建议**：要么加入 `.gitignore`，要么明确「它就是需要入仓的配置型数据」——需你确认语义后再动（此前已就此问过一次，未决）。
