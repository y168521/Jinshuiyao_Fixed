# 全项目诊断与重新规划建议（2026-08-12）

> 产出：opencode | 依据：3 路并行深度盘点（server/frontend 层、domains/engines/core 层、tools/流程/测试层）+ 6 轮网上调研（契约测试、Agent Registry/编排、工具生命周期、技术债务治理、Strangler Fig、Boring Architecture）
> 结论先行：**项目不需要推倒重来**。骨架是好的（26 个 handler 24 个真实、989 个真断言测试、15 个定时任务真实运行）。病根是"治理层形同虚设 + 注册表被绕过 + 自动化断线 + 没有验收标准"，用 Strangler Fig 式渐进改造，3 批内可基本治愈。

---

## 一、诊断：5 大根因（每条都有实证）

### 根因 1：没有单一真源，同类数据多份并存、各自漂移
| 证据 | 位置 |
|---|---|
| 基金名单 3 套（持仓/内置池/监控）→ JS-20260811-07 已合一，但对比/回测仍有重复实现 | server/handlers/fund.py vs backtest.py（双份 handler 几乎逐行相同） |
| 同一功能双副本页面 3 组（sources-health / omission-heatmap / lottery-dashboard） | frontend/lottery + jinshuiyao-guide |
| 3 个"audit"互不相关（core/audit_log 审计日志 / engines/audit 号码校验 / jinshuiyao/audit 足彩自愈） | 同名词不同物 |
| 命中率口径历史 3 套（GUI/API/验证器）→ JS-20260724-02 已统一，但 _PLAY_EXPECTED 仍双处硬编码 | prediction_service + brain_daily:29-45 |
| 跨设备同步子系统"注册但不存在"（/sync 4 条路由 100% 500） | server/handlers/sync.py + config.py:66 |

**后果**：改一处漏一处 → 每次优化都"换汤不换药"。

### 根因 2：注册表/编排层形同虚设，"智能体"从未真正接电
| 证据 | 位置 |
|---|---|
| core/agent_hub.py（305 行，15 agent）**全库 0 引用**；scheduler 15 个同名任务自行实现 → 幽灵孪生 | core/agent_hub.py |
| core/registry.py + domains/__init__.py 注册表完整但 `init_domains()` 从未被调用 | 生产路径全部直连 |
| engines/__init__.py 20 条注册表 `get_engine` 无生产调用；`"audit"→SchemeAuditor` 与实类 `Audit` 不符（必失败） | engines/__init__.py:35 |
| knowledge/kb_engine.py（769 行）0 生产引用 | knowledge/kb_engine.py |
| 5 个引擎共 2804 行仅注册表+测试引用（health_check/watchdog/sync_manager/plugin_manager/audit） | engines/ |
| lottery domain `analyze()` 是状态桩（返回 status:"ready" 无计算） | domains/lottery/domain.py:120-133 |
| ai_agent 派发域表缺 fund（fund 只能走 HTTP/GUI） | core/ai_agent.py:106-125 |

**后果**："智能体宛如智障"不是模型不行，是**注册了但从没接线**——这是用户感受的最直接来源。

### 根因 3：防空壳靠"事后人肉"，不是"机器强制"
| 证据 | 位置 |
|---|---|
| 契约检查器 page_api_lint 是本次才建的；4 个彩票 API 死链入库运行（PENDING 名单 WARN 不阻断，无过期时间） | tools/page_api_lint.py:28-33 |
| mock 兜底静默：football 无 CSV 返回 `[]` 无告警；预测降级硬编码 33.3%；holdings 页以前纯 mock（已修） | football.py:136-161 |
| AI 审查 fail-open（超时/无密钥/解析失败一律放行） | tools/precommit_ai_review.py:80-97 |
| 代码体检门禁 WARN-only 永不阻断（241 文件超阈值） | tools/code_health_gate.py:32 |
| 收工三件套检查=全文搜今日日期字符串即可通过 | tools/closeout_gate.py:53 |

**后果**：空壳能带着"已完成"标签入库，问题只解决表面。

### 根因 4：自动化断线 10 天，宣称的"全自动"多数空转
| 证据 | 位置 |
|---|---|
| 自动同步.ps1（蒸馏/数据守卫/索引保鲜第 6/7/8 步）**已无人调度**，实际任务只跑裸 bat | 计划任务 → 同步代码.bat |
| 操作留痕引擎**从未落盘一行**（审计轨迹.jsonl 不存在），/audit-dashboard 是空看板；pre-commit 无任何 audit_trail 调用 | tools/audit_trail.py + .git/hooks |
| GitHub CI 纯装饰：`cd Jinshuiyao_Fixed`（不存在）+ 全部 `|| true` | .github/workflows/code-review.yml |
| gate --e2e / --quality 引用不存在的脚本，必失败 | tools/gate.py:37、scripts/quality_gate.py |
| mirror_closeout 每日 23:30 调错路径脚本，静默失败 | core/automation_mirror.py:33 |
| 规范源 hook（wrapper）缺 page_api_lint 第 3 步 → 自愈/换机会装回旧版钩子 | tools/pre-commit-hook-wrapper.sh |
| 知识网关索引 8/5 后未刷新；经验蒸馏 8/2 后停摆（30+ 条新经验未进 Skill 区） | 知识网关索引.md |

**后果**：写了文档说"自动"，实际没人跑 → 信任崩塌。

### 根因 5：没有验收标准（DoD），"完成"=自己说了算
- 每次登记"已完成"前，没有强制清单：API 有没有契约测试？页面有没有浏览器验证？入口有没有全同步？mock 兜底有没有诚实标记？
- 没有技术债务登记册：PENDING 名单、半成品（情绪日报生成脚本缺失 JS-20260811-03）、断线自动化，全靠交接中心一句话，无 owner 无过期日 → 债务永续累积

## 二、对标成熟模式（调研结论，可直接借鉴）

| 成熟做法 | 来源 | 对金水谣的启示 |
|---|---|---|
| **契约即真相**：消费者契约→生产者 CI 验证；mock 从契约生成、与真实 provider 定期 shadow 校验 | Pact/CDCT、mock-drift（phillipmorrow） | 我们已有 page_api_lint（方向对）。补：契约测试进 pytest（本次已补 11 项）；页面 fetch 契约应由"前端测试"生成而非手写名单 |
| **Mock 生命周期**：mock 是设计工具不是交付物；上线必须有 staging 验证；无 mode 标记的兜底数据=缺陷 | Naftiko Capability Lifecycle（mock→staging→prod 两门禁） | 我们的 mode 诚实标记方向正确；补：检查器强制"兜底路径必须带 mode 标记"，否则 FAIL |
| **Agent Registry 必须被消费**：注册表不在调用路径=文档；EDDOps：agent 出生即 DRAFT，评估门禁晋升，陈旧自动降级；工具 4 阶段废弃（deprecate→log→opt-in→remove）+ 每工具 owner | Agent Registry 2026 Field Guide、EDDOps（arxiv 2607.00345）、The Dead Tool Nobody Can Remove | agent_hub 要么被 scheduler 消费要么删除；每 agent 加 owner+评估证据；死代码走 4 阶段废弃而不是一次性大扫除 |
| **DoD + 债务登记**：定义完成标准（测试含失败路径、文档同 PR 更新、快捷键当场登记）；债务 P1-P4 分级、20% 产能、例外流程带 owner+过期日 | TechDebt.solutions、AQAPro DoD 模板 | 交接中心"已完成"登记前过 DoD 清单；新建技术债务登记册 |
| **Strangler Fig**：不重写，按业务能力渐进替换，MVP 优先低依赖高价值 | Fowler、Azure Architecture Center | 第二批按此思路：彩票 4 API 逐个真引擎替换 mock 页，而不是"规划大重构" |
| **Boring Architecture**：删除>添加、无 3 个真实调用者不抽象、无证据不下结论、禁止 utils/helpers/misc 式目录 | Python 2026 Operating Standard、engineering kernel | 死代码清理常态化（本次盘点出 ~6000 行可候选）；"越简单越好"写入契 |

## 三、重新规划方案（3 批渐进，不推倒重来）

### 第 0 批：止血（1-2 次会话，纯删改不开发）
1. 修自动化断线：计划任务改回同步.ps1 全链路（或把第 6/7/8 步搬进同步代码.bat）；删/修 gate --e2e/--quality 死引用；修 automation_mirror 路径；**修复或禁用 GitHub CI**（装饰性 CI 比没有更糟）
2. 审计留痕接线：pre-commit 第 4 步真调 audit_trail（提交事件+bypass 检测），让 /audit-dashboard 出真数据
3. hook 规范源同步 page_api_lint 第 3 步，消除漂移
4. 删 sync.py 死路由 + static.py 死条目；删 3 组双副本页面的旧副本（统一走 frontend/）
5. 建《技术债务登记册》deliverables/技术债务登记册.md（本次盘点全部 P1/P2 项入册，带 owner/严重度/过期日）

### 第 1 批：单一真源+注册表治理（决定"删还是接线"，2-3 次会话）
1. **agent_hub 三选一**（用户决策）：a) scheduler 任务改走 agent_hub 统一入口（推荐，1 次会话）；b) 保留为文档型注册表+加"一致性检查器"校验注册表与 scheduler 任务名对齐；c) 删除
2. registry/init_domains：接线（ai_agent._get_domain 改走注册表）或删除
3. engines/__init__ 注册表：修 audit 错位；删 0 消费条目或标注 archived
4. fund.py vs backtest.py 双份实现合一（保留一个入口，另一个转发）
5. football 诚实降级：CSV 缺失返回显式 unavailable+mode 标记，删虚构赛程兜底
6. lottery domain analyze() 状态桩补真实计算或删除

### 第 2 批：防空壳闭环+业务深化（按 Strangler Fig 逐个替换）
1. 彩票 4 个死链 API 建真引擎（historical-same-period / number-follow-up / omission-table / trend-classification），建完**移除 PENDING 名单**
2. 检查器升级：PENDING 名单加"入库日期+到期日"，过期自动 FAIL；兜底数据无 mode 标记=FAIL；football 同理
3. 顶层仪表盘 + 探路闭环（fail 节点自动进债务登记册）
4. 新增功能一律走 DoD 清单（见下）

### 新功能 DoD（写进契，收工门禁强制核对）
一个"已完成"必须具备（缺一不许登记）：
- [ ] 后端 API + 该 API 的契约测试（pytest 真断言）
- [ ] 前端接线 + 失败路径诚实提示（无静默 mock 兜底）
- [ ] 路由注册（GET+POST 两分支）+ Hub/控制中心/导航指南入口同步
- [ ] page_api_lint 全绿（新 API 不允许进 PENDING）
- [ ] 真实数据验证（不是只看逻辑）+ 浏览器过一眼
- [ ] 交接中心/总索引/经验箱三件套登记 + 债务登记册同步
